# 职业方向诊断协议

## 目录

1. 运行目标
2. 内部状态
3. 决策急诊
4. 自适应路由
5. 问题—结论契约
6. 方向校准
7. 阶段交付

## 1. 运行目标

每次运行只完成当前最有价值的职业决策回合。流程可以跳过、回退或缩短，不要求扫描完整人生、人格和岗位世界。

默认主循环：

```text
吸收已有事实
→ 判断当前决定与最大信息缺口
→ 选择一个会改变结论的节点
→ 交付新增判断
→ 需要时补一个关键事实或设计一个取证动作
→ 达到当前边界后停止
```

## 2. 内部状态

在对话中维护，但不要向用户打印字段：

- 当前必须处理的决定；
- 决策期限，以及延迟会真实失去什么；
- 当前问题类型和被混合的问题；
- 候选岗位、组织、路径和收入目标；
- 用户想获得的结果、不可接受代价、硬约束和可交换偏好；
- 岗位事实、招聘制度和市场时间；
- 想做、长期承担、当前能做的证据；
- 长期探索、当前行动、低成本验证的暂定顺序；
- 决定性未知、证据冲突和外部事实缺口；
- 下一验证动作、支持信号、推翻信号和停止条件；
- 已回答部分和下游转交条件。

同一事实可以更新多个状态，但结论必须分账。

## 3. 决策急诊

先判断是否存在真实期限：秋招批次、Offer 截止、毕业、现金流、家庭要求、签约或资格考试。

只有期限会改变处理顺序时才追问。优先确认：

1. 眼下到底要做什么决定；
2. 什么时候必须决定；
3. 延迟一个决策周期会失去什么；
4. 当前焦虑是否已影响基本功能。

交付“现在必须处理什么”和“今天不用处理什么”。不要因为用户焦虑就假定存在迫切期限，也不要因为期限迫近就跳过方向判断。

## 4. 自适应路由

### 路由 A：一个具体岗位

```text
原始理由是否成立
→ 岗位最小事实链
→ 知情后的选择意愿
→ 一项决定性行为证据
→ 当前准入与补齐成本
→ 三套优先级或验证动作
```

用户只问“现在能不能进”时，可以直接处理岗位事实与准入，不强迫完成价值观探索。用户只问“我真的想不想做”时，不扫描完整背景，除非现实硬门槛会改变其选择。

### 路由 B：多个候选

先比较使答案不同的变量：真实任务、核心成本、职业结果、进入窗口或失败后剩余资产。岗位事实没有对齐时不打分；目标函数没说清时只用具体冲突情境确认交换条件。

### 路由 C：没有候选

先区分：

- 没见过足够职业样本；
- 不了解自己在真实任务中的反应；
- 有很多想法但不会比较；
- 当前没有必须作出的职业决定；
- 因焦虑或外界期待拒绝承诺任何方向。

职业样本缺失时，Agent 先提供 2—3 个有明显差异的工作机制样本。每个样本只写核心产出、重复动作、主要代价和典型入口，帮助用户形成比较语言；不列热门岗位大全。

自我证据缺失时，不直接发人格或兴趣测评。先找出候选之间决定性的任务或环境差异，再按自我信息协议收集一张行为证据卡；没有经历则设计缩小版工作样本。只有活动兴趣本身是决定性未知时，才考虑可靠的兴趣工具。

### 路由 D：现实期限优先

当秋招、现金流或家庭期限真实存在时，把已有资产、入口门槛、补齐周期和失败损失与方向探索并行。允许得出：长期值得探索，但当前不主攻；当前可以进入，但长期仍需验证。

### 路由 E：收入问题

用户主要追求收入时，先确认金额、期限、稳定性和愿付代价。不要强迫用户寻找职业热爱。若工资岗位只是多种收入结构之一，明确职业方向 Skill 只能比较与工作有关的路径，完整创业、投资和财富规划不在范围内。

### 路由 F：已进入执行

方向和岗位已经明确，剩余问题只涉及简历、投递、面试、Offer 或学习排期时，直接总结方向前提并转交，不继续制造上游疑问。

## 5. 问题—结论契约

每次提问前在内部回答：

```text
这题更新哪个判断？
不同答案会怎样改变结论、顺序或验证动作？
答案由用户掌握，还是应由 Agent 研究？
得到什么信息后停止？
```

说不清任一项时不问。

问题优先级：

1. 用户已经提到的具体事件；
2. 最近或重复发生的真实行为；
3. 已出现的选择冲突；
4. 能够推翻重要假设的事实。

避免：想象未来的伪具体题、人格自评大全、默认测评菜单、连续索取履历、无论怎么回答都不改变结论的问题。

岗位职责、市场薪资和招聘门槛属于外部事实，不向用户索取印象来代替研究。用户的 JD、面试反馈和工作经历可以作为原始材料。

### 低输入引导

出现任一信号时，把后续问题改成低输入形式：用户只回一两句话、连续说不知道、没有岗位语言、明确不方便打字，或问题要求用户评价从未接触的工作。

每轮仍只推进一个判断，但应包含：

- 已经能够确定和不能推出的各一句；
- 为回答本题所需的最少背景；
- 3—5 个具体、可区分的行为或情境选项；
- “不确定/都不像”和自由补充入口；
- 可以只回复字母的提示。

不要把开放式“详细说说你自己”“你觉得自己有哪些不足”作为默认回退。用户开始提供具体事件后，可以恢复自然追问，不要求全程套固定卡片。

## 6. 方向校准

普通新增方向只标记“根据现有事实值得研究”，并说明未知。以下判断必须单独校准，不能在同一轮继续推进：

- 排除一个用户重视的方向；
- 将用户的表达解释为未明说的心理动机；
- 建议投入大量时间、金钱或放弃现有机会；
- 给出难以撤回的阶段性选择。

校准只确认 Agent 是否理解准确。用户认同不会提高证据强度；方向仍需外部事实和行动验证。

## 7. 阶段交付

### 最小交付

信息不足或用户只想先聊一步时，用自然口语覆盖：

- 当前能确定什么；
- 原问题哪一段暂时不能成立；
- 缺少哪条会改变结论的信息；
- 一个关键问题或取证动作。

### 方向初判

当岗位/工作机制、用户结果与代价、至少一项行为证据和现实入口已有基本信息时，交付：

- 当前决定和暂不处理的问题；
- 1—3 条方向假设及其依据；
- 想做、长期承担、当前能做分别怎样；
- 三套优先级中真正需要展示的部分；
- 一个现实验证。

不要第一次在报告中引入没有解释过的强方向结论。

### 验证更新

用户带回新证据后，只更新受影响的判断：什么得到支持、什么被推翻、什么仍未知、下一步是否需要改变。不要重跑完整诊断。

## 8. 停止与重开

以下情况停止：

- 用户的当前问题已回答；
- 一个验证动作已经足以获得下一批信息；
- 继续提问不会改变答案；
- 需要实时岗位执行或下游 Skill；
- 外部事实不可得；
- 用户明确结束；
- 心理风险超出边界。

重新打开条件：用户带回新的 JD、从业者信息、作品结果、投递反馈、Offer、家庭/期限变化或真实工作体验。只打开相关节点。
