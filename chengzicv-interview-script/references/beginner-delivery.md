# 小白适配：能先照着练，再用自己的话讲

## 从现有材料判断，不先让用户配置

初次面试、只会念简历、不知道什么算项目、回答跳跃或材料很短时，自动降低表达门槛。不要先让用户选择 STAR、答题风格、框架、模式或能力等级。

有 JD 就由模型提炼岗位真正要做的事情；没有 JD 但有岗位名时先按已知方向组织，不虚构公司的具体要求。只影响次要内容的未知不阻断全稿。

用用户能答的问题采集事实：

- 那次你在帮谁解决什么事情？
- 哪一部分是你亲手做的？你具体做了什么？
- 后来交出了什么，或怎么知道事情做得怎么样？

这些是可选追问方向，根据当前缺口只问必要项，不要求一次把三问和完整故事都回答。用户回答后直接替其组织，不能再把模板推回给用户填。

## 没有大项目也可以讲真实经历

课程作业、社团活动、兼职、实习中的小任务、亲自完成的作品都可作为能力证据。标清场景、本人角色和结果，不把课程作业升级为商业上线项目，也不把协助包装成负责人。

不要为了故事完整必加失败、冲突、心理活动或量化成果。没有数字时用实际交付物、发现的问题、修改动作或已确认反馈说明。若不足以支持目标岗位要求，给已有迁移证据和诚实边界，不制造成熟经验。

## 一份稿里给不同深度，不重复三份文档

自我介绍默认只给一份完整可说稿；对方只给很短时间或用户要求短版时再补简版。项目短答直接可说；追问展开接在对应问题后，能辨认该从哪一句继续，不靠读者自行把素材拼起来。

给必要的过渡台词，让新手知道怎么进入下一段：

- 已让介绍：直接问好并进入介绍，不再询问能否介绍。
- 问到项目：直接回答这次问的角度，再提供相关经历。
- 对方打断：停住原段，接新问题；不用解释自己还没讲完。
- 对方结束：再进入反问或告别；不主动替对方结束面试。

候选人说话的段落保持普通正文。动作标注最多说明当前需要做的事；不要每句标情绪、眼神、笑容或音量，把人变成表演者。

## 想先学案例时

用户明确“我先看一个例子”“给小白案例学习”时，可以先交付完整教学案例，不强制索取个人简历。标题紧邻标明“教学示例，非你的经历”；教学人物和经历与个人台词分开。

案例里的背景、行动与结果要在同一个示例里自洽。若要讲数字，明确示例统计方式，不能只堆“增长 30%”这类亮点。用来学习的故事不能自动带入后续用户的个人材料。

案例主稿仍按开场、自我介绍、项目问题与追问、反问、告别顺序写完整，不用一串占位符。末尾说明怎样换成自己的事实：保留回答顺序，替换任务、个人动作、已知结果；没做过的部分删掉，不只替换姓名和公司。

## 末尾教学包：对照、阶梯、踩坑

小白的问题不是读不懂稿，而是看不出稿好在哪里、练到什么程度算会。末尾按固定四件组织，总量控制在一屏以内：

1. **改前改后对照（1—2 处）**：挑本次稿里最关键的一两处，把"没经验的人通常会怎么答"和"稿里怎么答"并排写，各一句点破差别（是否先答被问的、数字有没有口径、团队与个人有没有分开）。对照必须从本稿真实内容里挑，不编通用的反面例子。
2. **脱稿四级阶梯**：每级带过关标准，过不了就留在该级，不往下赶：
   - L1 照稿朗读：开场和自我介绍能一口气读完、不磕巴。
   - L2 关键词复述：盖住稿，按"当时的事—我的动作—已知结果"三个线索重讲一个项目，事实不走样。
   - L3 换问法：把同一段经历用另一个问题引出（如换成"你最有成就感的事"），能直接回应新问题，而不是背回原稿。
   - L4 干扰演练：找人中途打断追问一次，能停下原段接新问题；或自己录音回听，确认每段先答了问题、在重点处停住。
   用户赶时间时只练 L1、L2，并明说剩余两级的风险（现场被换问法或打断时容易卡壳）。
3. **常见踩坑对照（最多 3 条）**：只列与本稿相关的，每条写成"听着像什么 → 问题在哪 → 稿里怎么处理"。例如：一口气把项目讲完不分段 → 面试官没有插话空间 → 稿里先短答、停顿、等追问。不抄通用面试禁忌清单。
4. **哪里要确认**：只列会影响事实可信度的具体问题；没有缺口就不硬凑。

给用户可自查的总标准：能先回答问题，不新增事实；讲完重点后能停；被打断后能换到新问题；不看稿仍能讲清自己做了什么。不要把"稿子写好了"说成已经学会，也不承诺完美适配所有公司和面试官。用户练完 L4 仍想验证时，建议转 `chengzicv-interview-mock` 做一轮现场问答——只建议这一个下一步。
