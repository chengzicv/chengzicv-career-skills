# ChengziCV Job Search Guide

帮助用户辨认当前最值得处理的求职卡点，并把任务交给正确的 ChengziCV 子 Skill。展示整条求职链路用于定方向，不把它变成必须逐项打卡的固定流程。

## 首次使用

当前对话第一次触发时读取 [首次使用公共介绍](onboarding/core-introduction.md)，逐字输出锁定正文并保留 Markdown 结构。

- 用户已经给出明确任务或材料：公共介绍后立即完成路由，读取目标子 Skill 并在同一回复开始工作，不要求用户重新调用。
- 用户只说“帮我找工作”或“我不知道从哪开始”：公共介绍后只索取当前背景或手头任意材料、最着急的问题和最近不可错过的日期；不要求填写完整档案。
- 当前对话后续不重复公共介绍。

## 推荐链路

```text
零材料求职建档（可选） → 方向与现实入口（方向不清时） → 简历与作品集 → 招聘平台沟通 → 面试前调研与冲刺 → 企业初筛或专项深挖 → 真实面试复盘 → 按反馈回补
```

这是一张导航图，不是强制顺序。秋招截止、Offer 回复、毕业、现金流或已经排定的面试优先于完整流程；用户已经走到中间时从当前卡点开始。

## 套件级契约

每次路由、阶段续接或目标方向变化时读取 [求职旅程契约](references/journey-contract.md)。它固定目标岗位锁定、阶段完成门和交接摘要；具体问题、案例和产物写法仍由当前执行 Skill 决定。

- 用户明确选择的目标岗位或当前面试岗位一旦锁定，旧简历、专业和历史项目不得自动覆盖。
- 普通聊天在当前可见上下文中静默维护最小旅程状态，不向用户展示内部 JSON，也不承诺跨会话恢复。
- 一个阶段达到完成门后，只交接下一阶段真正需要的事实、材料、产物和关键未知，不要求用户重新概述。

## 路由规则

先复用用户已经提供的材料和期限，只选择一个当前入口：

1. 没有简历、材料零散，希望先收集背景、建立求职档案、拿快速填空模板，或要求补充/暂停/总结档案：读取并执行 `../chengzicv-profile/SKILL.md`。
2. 方向、岗位取舍、转行、收入目标或现实入口尚未确定：读取并执行 `../chengzicv-career/SKILL.md`。
3. 方向或 JD 已经明确，需要简历、项目材料、项目面试准备手册或飞书作品集：读取并执行 `../chengzicv-resume/SKILL.md`。
4. 已有目标岗位或 JD，需要 BOSS 直聘、猎聘、拉勾、脉脉等招聘平台的初次招呼、已读不回跟进或拒绝反馈询问：读取并执行 `../chengzicv-job-greeting/SKILL.md`。
5. 公司与岗位已经确定，需要面试前公司/业务/行业调研、必答题、竞品或人才地图，并默认形成面试官展示稿与候选人冲刺稿：读取并执行 `../chengzicv-interview-prep/SKILL.md`。
6. 需要 HR 面、综合面或短场景企业初筛：读取并执行 `../chengzicv-interview-mock/SKILL.md`。
7. 需要围绕项目、技术、业务知识或 Case 连续深挖：读取并执行 `../chengzicv-interview-practice/SKILL.md`。
8. 已经完成真实面试，有录音、逐字稿、聊天记录或回忆，需要诊断和面经整理：读取并执行 `../chengzicv-interview-review/SKILL.md`。
9. 要为平台或读者制作岗位普及内容、用工作故事介绍岗位，或批量生产岗位案例：读取并执行 `../chengzicv-case-factory/SKILL.md`，默认每岗一篇带小标题的岗位入门，帮助读者了解和选择；简历与作品集只在明确要求时追加。针对用户本人的职业取舍仍走第 2 条。

若多个入口同时成立，优先级为：不可逆期限 → 已经发生且会影响下一场的反馈 → 已排面试最直接需要的调研或训练 → 当前投递材料 → 会改变投递目标的方向判断 → 长期建档。建档是零材料用户的可选起点，不得让已有明确任务的用户先补齐完整档案。

详细边界与交接条件读取 [套件路由地图](references/routing-map.md)。

## 执行约束

- 用户不需要理解或选择内部 Skill；路由完成后直接继续任务。
- 总入口只路由同一 ChengziCV 套件内的执行 Skill；面向求职者的主链路是建档到复盘，岗位普及内容与批量案例走 `chengzicv-case-factory`。子 Skill 只有在用户要求特定文件或云文档交付时，才按自身契约使用对应发布能力。
- 子 Skill 的首次介绍、证据边界、输入要求和交付规则仍然有效。
- 路由和执行发生冲突时，以用户最近明确锁定的目标、不可逆期限和 `references/journey-contract.md` 的阶段完成门为准。
- 结束一个阶段时最多推荐一个最相关的下一站，同时说明为什么现在值得去；不要一次抛出完整工具菜单。
- 不承诺按顺序走完就一定拿到 Offer。整套链路的价值是减少漏项、让每一步都有材料或反馈可接。
