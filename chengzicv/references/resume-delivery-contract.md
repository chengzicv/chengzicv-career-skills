# 简历成品交付契约（三入口共用）

适用范围：用户提供简历、零散经历或 JD，并期望拿到「能直接投出去的简历」时。无论从 `chengzicv`、`chengzicv-resume` 还是本机安装的排版增强技能进入，都按本契约执行——**入口只决定先读哪份规则，不决定交付范围**。

## 默认交付（A4 HTML + Markdown 源稿）

1. **事实层**（`chengzicv-resume`）：按直述体与材料边界产出 Markdown 源稿；有 JD 时附 ATS 核对报告。
2. **呈现层**（默认）：按 `chengzicv-resume/assets/resume-document-template.html` 渲染 A4 打印版 HTML，用户在浏览器里另存 PDF 即可。
3. **交付**：同目录、同基名的 `.md` 源稿 + `.html` 成品，一次给出，不要求用户二次点名第二个 Skill。

简历成品是整套里唯一保留 Markdown 源稿的产物，其余交付件只出 HTML。

## 可选：GodSU 风格版式

只有用户明确要 GodSU 风格、带 logo 的排版或现成 PDF 文件，且本机装有对应排版增强技能（公开包内不含）时，才续跑它：把定稿 Markdown 洗成高信号版式，输出 HTML + PDF（logo、荧光笔高亮、单页优先），与源稿同基名。

用户没点名时不做这一步，避免同一份简历出现两套视觉。

## 入口行为

- **从 `chengzicv` 进入**：路由到简历阶段后走「事实层 → A4 HTML」，不停在 Markdown；用户点名 GodSU 或 PDF 时再接 GodSU。
- **从 `chengzicv-resume` 进入**：同上，默认出 A4 HTML + Markdown 源稿。
- **从排版增强技能进入**（本机安装时）：若输入是原始简历或零散材料而非定稿，先按 resume 规则做事实稿（挖料、防伪审计、直述体、个人优势），再排版；同一轮交付，不拆成两次会话。
- **用户明确只要某一形态**（只要 md / 只要排版 / 只要 PDF）：单点执行，不补走另一端。

## 事实与风格边界

内容取舍、数字口径、证据边界只由 resume 层决定；呈现层不新增事实、不改数字，只做句式密度、结构、排版与视觉。冲突时以 resume 层为准，风格层降级措辞或删除。

## 失败降级

渲染不可用（无浏览器、无法写盘）时，交付 Markdown 源稿并说明缺失的形态与原因，不因此卡住事实稿。
