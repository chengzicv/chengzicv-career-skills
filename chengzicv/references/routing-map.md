# ChengziCV 套件路由地图

## 执行入口

| 当前卡点 | 入口 | 结束时至少得到 |
| --- | --- | --- |
| 没有简历、材料零散，想从零收集背景或随时维护档案 | `chengzicv-profile` | 求职档案快照、材料索引、待确认项和下一步 |
| 不知道选什么、为什么选、现在能否进入 | `chengzicv-career` | 当前决定、少量方向假设、现实验证动作 |
| 有目标或 JD，但材料还不能投、项目证据尚未整理 | `chengzicv-resume` | 可投简历、证据缺口；需要时含项目双文档与作品集 |
| 已有目标岗位或 JD，需要招聘平台初次招呼、已读不回跟进或拒绝反馈询问 | `chengzicv-job-greeting` | 预览信号、可直接发送的话术、跟进边界与测试版本 |
| 公司与岗位已确定，要做面试前业务调研、完整答案和双文档 | `chengzicv-interview-prep` | 面试官展示稿、候选人冲刺稿、来源与待确认项 |
| 简历已有，需要讲自然、写口语台词或静态技术备答 | `chengzicv-interview-script` | 场景台词、分段项目回答、追问、收尾与关键待确认事实 |
| 要准备 HR、综合面或短场景初筛 | `chengzicv-interview-mock` | 一场短模拟、证据诊断和复练任务 |
| 要深挖项目、专业知识、业务判断或 Case | `chengzicv-interview-practice` | 连续追问、教学、变式复测和阶段复盘 |
| 面试已经发生，需要还原和复盘 | `chengzicv-interview-review` | 逐题面经、证据诊断和下一场改进项 |
| 为平台或读者制作岗位普及内容、工作故事或批量岗位案例 | `chengzicv-case-factory` | 每岗一篇带小标题、融合工作故事与岗位选择的 Markdown；简历、作品集按明确要求追加 |

## 改变默认顺序的条件

1. 有明确截止日期：先保住当前机会和必要材料。
2. 即将面试：缺公司/岗位理解和完整答案时先做面试准备；只缺口语表达或衔接时直接做台词本；需要现场检验时再选最贴近轮次的模拟或专项训练。材料问题只修会直接影响面试的部分。
3. 刚完成面试：先复盘，趁记忆完整提取证据，再决定回补简历还是训练。
4. 方向会改变简历目标：先做最小职业判断；否则直接改材料。
5. 完全零材料但问题只是“先整理我有什么”：先建档；如果核心是选方向，直接做职业判断，不强制先填完整档案。
6. 只有长期焦虑、没有当前窗口：从职业方向或零材料建档中选择最贴近当前问题的一步。

## 反馈回路

```text
零材料档案留下背景、经历和材料证据
→ 职业假设决定简历目标
→ 简历暴露证据缺口
→ 招聘平台沟通把岗位证据压缩成预览信号，并记录回复反馈
→ 面试前调研把目标公司、岗位和答案接起来
→ 面试台词本把真实经历组织成可说的场景回答
→ 模拟与专项训练检验表达和专业能力
→ 真实面试反馈指出最该回补的环节
→ 只回到出现问题的那一步
```

不要因为展示了全链路，就要求用户把所有执行入口都走一遍。

## 路由时保留什么

总入口内部按 `journey-contract.md` 维护当前阶段、目标岗位及其锁定状态、已有材料、已完成产物、关键未知和下一动作。对用户只输出自然语言承接，不展示内部字段。

若用户已经明确“这次就投/面某岗位”，目标立即锁定。简历原专业、旧项目方向和模型推断只能帮助寻找迁移证据，不能把后续任务带回旧方向。
