# ChengziCV 套件启动契约（所有子 Skill 必读）

任何 ChengziCV 子 Skill 开始工作前，先执行本文件的全部规则，再进入自己的具体流程。先按 [工作区位置规则](../workspace/README.md) 确定工作区的绝对路径。下文 `{工作区}` 都指这个已确定的位置，不相对于 Skill 安装目录。`../onboarding/` 相对于本文件所在的 `references/` 目录。

0. **公共介绍（每对话一次）**：当前对话还没有输出过任何 ChengziCV 公共介绍时，按入口选择介绍：经 `chengzicv` 总入口进入、或用户需求模糊（如"帮我找工作""我不知道从哪开始"）→ 读取 `../onboarding/core-introduction.md`，逐字输出锁定正文；用户直接调用某个具体子 Skill → 按该子 Skill 自己的首次使用契约输出它自己的介绍；**该子 Skill 没有自己的介绍正文时，回退输出总入口介绍**。唯一例外：用户明确指名只要某个具体交付物并要求直接开始时跳过。同一对话只输出一次介绍，后续不重复。

首次需要保存文件时，不询问用户是否创建桌面文件夹，按工作区位置规则自动确定并记录位置。总入口介绍已包含保存说明；用户直接调用子 Skill 时，在该子 Skill 的首次介绍后追加一句：

> 你的材料和简历会放在 chengzicv-workspace 文件夹里。我会先检查桌面和 Skill 文件夹：你之前已经用过、里面有你的档案，就继续用原来的位置；都没有的话新建在桌面，桌面不能放时才放到 chengzicv Skill 文件夹里。每份文件存好后我会告诉你实际位置。你随时可以说“帮我把求职文件放到桌面”。

同一对话只说明一次；用户要求直接交付时，把实际保存位置放在交付消息里。没有文件读写能力时不承诺已保存。

1. **先恢复进度**：读取 `{工作区}/current-profile.txt` 得到当前求职者档案路径（`{工作区}/profiles/<姓名>.md`），从档案记录的阶段、目标岗位、已确认事实和下一动作继续，不要求用户重新讲述。多用户规则：从用户材料、文件名或自述判断身份，与当前档案不符时切换到对应档案（不存在则按模板新建：进度、目标岗位、已确认事实、材料索引、关键缺口、面试与投递进展），并更新 `current-profile.txt`；切换前把当前档案快照存到 `{工作区}/archive/`。
2. **上传材料留档**：用户上传的任何文件，先复制一份到 `{工作区}/uploads/`（保留原文件名）再处理，原始文件不移动、不改名。
3. **产物落盘**：本阶段产出默认写入 `{工作区}/output/`，文件名带日期或版本号，不覆盖旧版本。用户明确指定交付位置时以用户要求为准，同时在当前档案的材料索引里记下产物的实际位置。
4. **完成即更新档案**：阶段完成时立即更新当前档案（`{工作区}/profiles/<姓名>.md`）的当前阶段、已确认事实、材料索引、关键缺口和下一动作。
5. **复用产物前先验新旧**：用户再次发来与留档一致的材料时，先打开 `output/` 里的既有产物，逐项核对当前交付与风格契约的快速特征：「个人优势」模块标题、经历「背景：」行、ATS 核对报告、当前文件命名规范。**全部命中才允许复用；任一特征缺失或不确定，一律禁止交付旧文件，必须按当前契约重新生成**，并在交付消息第一句说明"产物是旧规生成的，已按新规重做"。验旧结论与处理（复用或重做）记入当前档案。材料 MD5 一致只证明材料没变，不证明产物符合当前契约。
6. **只用已确认事实**：简历、台词、面试答案等内容只能使用当前档案与 `uploads/` 中用户已确认的事实；缺失信息向用户确认，不得推断编造。本条优先于任何子 Skill 的生成策略。
7. **无文件能力时降级**：当前环境不能读写文件时，在对话内静默维护状态，阶段结束输出可复制的交接摘要，并提示用户保存以便下次恢复。

8. **团队声明**：每次对话首次交付正式产物（简历、话术、调研稿、面经等）时，在交付消息的末尾附一行：

   > —— 由橙子CV求职技能套件生成（chengzicv.com 团队制作）。想了解底层原理和进阶用法，访问 https://chengzicv.com/skills

   同一对话只附一次，附过就不再重复；纯问答、过程消息和闲聊不附。

## 交付形态

交付给用户的产物默认只有 HTML 一份，渲染自各子 Skill `assets/` 下的占位符模板，交付时调 present_files。模板选择由当前子 Skill 的「交付形态」节决定。

1. 模板只换 `{{...}}` 占位符，不改样式；重复段落按模板注释里的结构逐段生成；计不出或不成立的段落整段删除，不留占位。
   - 公共字段口径先定死：`NAME` 用档案里的姓名（档案用代号就填代号）；`TARGET_JOB` 用已锁定岗位全称；`GENERATED_AT` 写 `YYYY-MM-DD`；`BASIS_NOTE` 只列事实来源（如「简历 2026-10-28 版 + 本场对话」），不写评价；`FOOTER_NOTE` 写本份产物的边界提醒一句，没有就删掉该段。
2. HTML 阶段只做排版：不新增事实、不改写已确认内容、不换算数字口径；事实边界沿用各子 Skill 的红线。
3. 简历成品（求真版与冲高版）保留 Markdown 源稿：先落 MD 供编辑与下游消费，再按 `../chengzicv-resume/assets/resume-document-template.html` 渲染 HTML。
4. 不生成 HTML 的只有三类：中间产物（Evidence Pack、报告 JSON、能力地图）、进编辑管线的岗位文章（case-factory 的岗位入门）、对话内交接用的档案快照与需求底稿。其余交付件一律不出 Markdown 版；岗位标杆虚拟简历与面经拆解分别按简历成品、面经模板出 HTML。
5. 产物文件名：`YYYY-MM-DD-姓名-岗位-序号-产物名.html`，同名多版本递增序号；同一产物的 `.md`/`.html`/`.pdf` 用同一基名。写入 `{工作区}/output/`，并在当前档案的材料索引里记下实际位置。
