# 产品边界：岗位理解与虚拟经历示范

## 核心目的

面向不了解岗位、尚在比较方向的读者，回答日常处理什么、成果交给谁、吸引力与麻烦是什么、与相近岗位差在哪，以及怎样进一步了解。同时用虚拟简历示范相关经历如何体现判断、过程、结果和复盘。

默认每岗交 `01-岗位标杆虚拟简历.md` 与 `03-岗位入门.md`。用户明确缩小范围时照办。作品集、面试手册、全套 PRD、练习包不是默认交付；复杂理工科岗位也不自动追加作品集。

## 深度边界

工作或实习经历使用 STAR＋复盘，保留个人职责和审批边界。优先加入需求、资源投入、执行与交付明确的小型经营或自主项目，不能只做浅层课设或改一个创业标题。详细标准见 `experience-depth.md`。

创业只是可选的经历形态。临床、药品、芯片工艺等受资格、设施和安全约束的岗位，不编造学生独立执业或高风险生产。自主服务、科研或技术项目也可以有同等深度。用户明确设定零经验时，不擅自添加任职；用能够成立的项目说明能力。

文章保留少量工作材料和一个轻量判断，帮助认识工作，不扩成完整培训。工具须解释输入、动作及用途，不展开安装、付费或逐菜单教学；AI 按实际需要出现。

## 研究与虚拟事实

Agent 主动查公开 JD、官方资料和必要的专业约束，不把寻找内部材料或访谈的任务交还用户。JD 支持职责与入口，不支持虚构业务结果。虚拟公司、人物、对话、报价、经营数据和任务进展单独记为情境设定，不冒充真实员工采访或企业业绩。

两份材料共享人物、公司、身份、时间、职责和数字。真实个人简历由相邻 resume Skill 按事实与证据规则处理；平台案例不自动成为真人经历。个人职业诊断另由 career Skill 处理。

## 展示与权限

平台统一说明案例属性，正文不重复加制作提示。内部事实与进度记录不进入发布正文。独立脱离平台交付的完整简历，在开头简短说明一次案例性质。对话中已明确要求虚拟案例的单段项目，可在交付说明中注明一次；用户要求仅三段式正文时不另塞第四段。片段后续单独外发时应保留案例性质说明。

生成本地稿、修改 Skill 和外部发布是不同动作。本 Skill 不默认执行外部发布；品牌“橙子 CV”保留，案例人物默认小橙。
