# 虚拟案例包：简历＋岗位入门

## 文件与一致性

每岗默认交 `01-岗位标杆虚拟简历.md`、`03-岗位入门.md`。用户已有文件名时沿用；只要求某一份时按其范围。大幅重做另存新版本，不覆盖用户确认稿。两份材料共用同一虚拟事实底稿，姓名、公司、时间、职责、数字和进展一致。

展示正文不含 frontmatter、内部编号、证据状态、制作提醒或重复免责声明。不默认生成作品集、CSV、空白模板、README 及质检报告。

## 虚拟简历

按 `../../chengzicv-resume/SKILL.md` 的「动笔前读取」「默认直述写法」「项目与经历结构」「头部与排版」「小抄与终检」执行。本文件不重复其规则，只补虚拟案例的四点：

1. 独立文件顶部保留一次案例说明；平台展示由平台统一说明。
2. 人物默认小橙，学校、公司、客户、奖项和数据全部虚拟化；不写真人姓名、真实公司或真实业绩。
3. 默认不输出追问清单、候选补全台账、ATS 核对报告、冲高版或小抄；用户明确要求时按 resume-latest 的对应规则追加。虚拟事实在 `_内部` 的 `scenario_facts` 锁定。
4. 简历与岗位入门共用事实；不能一份写周四仍缺 100 个，另一份却写周四全部完成。

## 岗位文章

按 `gold-standard.md` 的阅读顺序写：

1. 任务和材料开场，让读者看见要处理什么。
2. 说明谁付钱、谁使用、企业关心什么、各方怎样分工。
3. 用少量记录展示问题，邀请读者作一个判断。
4. 展开判断依据、方案取舍、工具动作、协作及交付。
5. 写清结果、代价和复盘，不把试用计划写成已验证改善。
6. 顺着任务谈工作感受、相近岗位差别、入门和读 JD。

经营项目若有助于解释专业与工作的联系，可在入门部分简要带入，不必把整份简历重复粘贴进故事。岗位普及仍需帮助读者选择，不能只剩个人履历或通用求职建议。

## 阅读层次

一个主标题，按内容转折使用具体的小标题。段落各讲一件事，表格用于记录或比较。篇幅以读者看懂为准，范文的篇幅仅作密度参考，不是配额。虚拟简历的篇幅按 `../../chengzicv-resume/references/one-page-markdown-rules.md`，本文件不另设字数要求。

术语随动作解释，工具有输入和产出，会议有待解决的问题。不要安排角色轮流讲方法论，也不要列全字段、操作步骤、所有验收条件和会议计划。跨多日写明跨度。

## 选择与交付

工作乐趣与琐碎都回到实际动作；不根据人格标签或一次练习判断适配。同名岗位可能职责不同，要区分基础要求、加分项与特定方向要求，并提供具体的 JD 阅读或面试提问方式。

默认交付两份 MD 链接和简短说明。批次自查完成后等待用户 check，不以内部完成状态代替用户确认。
