# 真实 offer 案例标尺（脱敏）

用途：回答用户"什么水平（项目经历水平）的简历能达到普通、中、大厂筛选标准"。给真实标尺，不给承诺——标尺展示的是"这样的人过了这样的筛选"，不是"照做就能过"。

来源：七份真实 offer 案例（2026-10-12 倒推，原件与提取文本存知识库 `09-技术/chengzicv-skill迭代参考/真实offer案例/`），人名、学校、公司、品牌、赛事名、地名、联系方式已全部虚拟化；数字与机制为信号载体按原样保留。

## 三方隔离

- 本文件是**真实脱敏案例**，与 `benchmark-resume-standard.md` 的小橙虚拟标杆是两类资产：虚拟标杆可自由设计，本文件一个字的事实都不能改编进小橙简历，小橙的虚构经历也不能混入本文件。
- 用户看过标尺后想改自己的简历，转 `chengzicv-resume`；标尺中的经历、数字不属于任何用户。

## 分档说明（诚实边界）

目前七份案例全部落在**大厂/知名公司档**（字节级、腾讯、拼多多、银行管培）。普通档、中小厂档没有已验证案例，不编。用户材料距大厂档差距明显时，用 chengzicv-resume 的补强建议指路，不虚构低档位标尺。

## 六型速查

| 类型 | 硬牌 | 已验证去向 |
|---|---|---|
| 实习测量型 | 知名实习 + 实验测量 | 字节级大厂 AI/全栈 |
| 自研纵深型 | 自研项目对标热点工程 + 论文 | AI 岗（Agent 开发） |
| 独立完整项目型 | 一人扛起完整商业系统 | 腾讯（Go 后端） |
| 业务数据型 | 上线项目业务数字 | 拼多多（重业务大厂） |
| 成绩资质型 | 排名 + 课程分 + 稀缺奖学金 | 银行管培（国央企） |
| 跨行迁移型 | 原行业可迁移业务成果 | 字节（项目管理实习） |

用法：先判断用户材料最接近哪一型，给对应标杆对照差距；不匹配任何型时用通用信号（难点前置、可追问细节、真实测量口径）对照。

## 标杆 1：实习测量型 → 字节级 AI 全栈

硬牌：行业头部公司实习 + 自测实验口径数字。硕士在读，211。

脱敏片段：

> **某少儿编程公司（行业头部）　AI 应用开发实习生**
> 针对 LLM 生成工程时易任意扩展文件、导致目录规范与运行时加载链路失配的问题，参与设计"工程约束校验—项目级 Linter—错误定位与结构化反馈—Fix Agent 修复"的自动修复流程；在 20 个标准化生成案例中，可运行率由首轮 20% 提升至自动修复后的 100%，平均修复 0.8 轮。
> 多 Agent 相比 Single-Agent 将关键事实召回率从 52% 提升至 65%（+13pp），安全违规率降低 3pp，但平均延迟增加约 1.64 秒。

为什么能过（信号注释）：
1. 每条都是"针对什么问题→怎么解"，难点前置；
2. 数字全是实验口径，带基线与样本（20 个案例、20%→100%）；
3. 敢写负面结果（延迟 +1.64 秒）——真做过实验的信号。

## 标杆 2：自研纵深型 → Agent 开发

硬牌：自研项目对标行业热点工程 + 中科院一区一作论文。无大厂实习。

脱敏片段：

> **轻量级本地 Coding Agent CLI（自研，参考主流编程 Agent 思路）**
> 13 个核心工具按 read/edit/shell/git/meta 五组延迟激活，read-only 任务前 5 轮节省 schema token 5K+；按工具副作用分级做同轮并发批切片与串行回退，纯读工具并发 wall time 降低 15% 以上。
> 编辑前校验文件被读过 + mtime 未变 + 内容指纹一致，外部修改时自动重读并拒绝写入；叠加 5 种权限模式 + 18 条危险命令正则的四层权限体系。

为什么能过：
1. 参数密度——每个机制都有可追问下一层的具体数字与设计；
2. 选题对标岗位热点工程，证明能读懂并复现行业前沿；
3. 安全与权限这类"不性感但专业"的环节写全，区分于玩具项目。

## 标杆 3：独立完整项目型 → 腾讯 Go 后端

硬牌：一个人扛起完整商业系统（交易/支付/物流/AI 集成）。

脱敏片段：

> **全链路模型交易与悬赏平台（Go + Gin + GORM）**
> 独立设计并实现一口价出售与求购竞标双轨交易引擎，求购模式支持投稿、选标、确认收货后按比例分账；设计展示层、订单层、物流层的复杂状态机联动，基于事务保障高并发预扣库存，超时未支付自动取消并回补库存；深度集成真实支付平台，实现自动分账（创作者 80%、平台 20%）；接入真实物流开放平台，完成运费预估、在线下单与单号回填。

为什么能过：
1. 全链路复杂度本身即信号——状态机、分账、库存回补都是深水区；
2. 对接的是真实第三方（支付、物流），不是 mock；
3. 模块齐全到"能上线"的程度，区分于课程 demo。

## 标杆 4：业务数据型 → 拼多多后端

硬牌：真实上线项目的业务数字。211 本科。

脱敏片段：

> 实习成果：系统日均稳定处理任务 17w+，累计管理 68 个 AI 应用；峰值 P99 约 220ms~230ms，平均响应延迟 10ms~11ms；RPM 约 1500。
> 个人项目成果：累计用户 3531 人，曝光用户数环比增长 106.47% 至 1.99 万；整体转化率提升 13.86% 至 66.50%。

为什么能过：
1. 数字全口径、不约分（106.47% 不写成翻倍），一看就是真数据；
2. 结构是传统三段式——**结构不限，数据本身就是信号**；
3. 实习指标（P99、RPM）与个人项目指标（用户、转化）分开归属。

## 标杆 5：成绩资质型 → 银行管培

硬牌：排名 2/58 + 核心课分数 + 稀缺性奖学金。财经类院校硕士。

脱敏片段：

> 加权成绩 90.38/100，专业排名 2/58（前 5%），CET6 525 分；核心课程：高等数学 100、Python 语言与数据分析 99；某励志奖学金 3 次、某自强奖学金（全院 570 人中仅选 4 人）。
> 实习成果：财报识别模块上传操作错误率下降 30%，审批流程平均耗时缩短 25%；开户成功率从 72% 提升至 88%。

为什么能过：
1. 国央企轨的硬通货（排名、课程分、奖学金稀缺性）全部前置；
2. 稀缺性写清分母（570 人中仅选 4 人），不写"成绩优异"类虚词；
3. 业务数字保留口径，跨境/合规经历（全英文需求文档、港资市场）加分。

## 标杆 6：跨行迁移型 → 字节项目管理实习

硬牌：原行业（建筑）的可迁移业务成果。普通本科。

脱敏片段：

> 教育亮点：系统学习建筑规划与设计方法，同时在多个校企合作与竞赛项目中积累了用户研究、需求分析、项目管理与跨部门协作经验。
> **某乡村校企合作中心建设　项目负责人**
> 用户研究与需求分析：为解决传统竹产业发展停滞问题，主导团队开展痛点拆解，输出 10+ 份、500+ 页方案 PPT，明确"竹产业+非遗文旅"核心方向。
> 方案策划与商业合作：实地访谈非遗传承人 10+、民宿与活动机构 15+，促成 10+ 份长期合作协议；推动项目立项并获得 150w 投资。
> 跨部门协作与落地执行：组织 50+ 次现场沟通，工期缩短 50%，门店日均客流提升 20%、日均流水提升 30%。

为什么能过：
1. 每段经历用目标岗位能力框架重新映射（用户研究/商业合作/落地执行），不让原行业术语独立堆砌；
2. 开头一句转岗论证，主动回答"建筑学为什么能做产品"；
3. 业务数字（150w 投资、客流 +20%）承担硬证据——跨行的可信度靠结果说话。

## 给用户做对照时的口径

- 先说"这份能过是因为这几张牌"，再说用户材料最接近哪型、差在哪；差距在材料层时转补强建议，不把改写包装成万能。
- 不承诺"改成这样就必过"；筛选因素多于简历能控制的部分。
- 六型的信号细节以 `chengzicv-resume/references/bigtech-signals.md` 为生成侧规则，本文件是展示侧标尺，两者事实一致、分工不同。
