## 核心模型

把专项面试看成一棵动态树，而不是预先生成的题单：

```text
岗位能力
→ 可观察行为
→ 候选人声明
→ 待验证证据
→ 原理与判断
→ 取舍和边界
→ 反事实与迁移
```

父节点未解决时，不猜测答案去问依赖它的子节点。候选人的每次回答都会改变树的结构和下一题。

## 节点状态

在内部使用以下语义，不必向用户展示标签：

- `未覆盖`：尚未取得回答。
- `已声明`：用户给出结论，但没有足够证据。
- `追问中`：已有部分事实，仍需核验。
- `已支持`：事实、个人动作和判断基本一致。
- `有矛盾`：与简历或前文冲突，尚未澄清。
- `明确缺口`：用户承认不会，或继续追问不再产生信息。
- `已教学`：已给反馈或讲解，但尚未证明掌握。
- `已复测`：在无提示变式题中再次表现出能力。

不要把“已教学”直接升级为“已支持”。

## 当前前沿

“前沿”是所有依赖已经解决、此刻可以可靠提问的节点。每轮只从前沿选择一个问题。

选择时综合判断：

- 与目标岗位的相关性；
- 当前不确定性；
- 是否能区分真实能力与表面表达；
- 是否能解锁更多下游分支；
- 是否与已问内容重复；
- 提问成本和候选人当前负担；
- 是否有待复测项目到了合适时机。

不要提前承诺固定题目顺序。回答改变上游判断时，重新计算前沿。

## 强制回合动作

每轮评估回答后只选择一个动作：

| 动作 | 使用条件 | 用户可见结果 |
| --- | --- | --- |
| `PROBE_CURRENT` | 当前分支仍缺关键证据 | 当前分支的一个追问 |
| `COACH_AND_REASK` | 逐题教练且需要继续 | 简短反馈、最小提示、一个重答或追问 |
| `CLOSE_TEACH_AND_ADVANCE` | 当前分支已支持、矛盾无法继续或明确缺口 | 分支反馈与教学，随后至多一个新问题 |
| `RETEST` | 待复测节点到期且没有待反馈分支 | 一个无提示变式题 |
| `FINAL` | 用户停止或没有高价值前沿 | 补齐未完成反馈后复盘 |

不要把动作混合成“跳过反馈直接换题”。可以在完成分支反馈后，于同一回复末尾提出一个新问题。

所有会要求候选人回答的动作都必须使用 `SKILL.md` 规定的问题卡：

- `PROBE_CURRENT`、`COACH_AND_REASK`、`RETEST` 每次各产生一张新问题卡；
- `CLOSE_TEACH_AND_ADVANCE` 先完成分支反馈，有下一题时再用分隔线开始新问题卡；
- `FINAL` 不生成问题卡。

## 状态不变量

始终满足：

```text
branch_status 由开放变为关闭
→ feedback_pending = true
→ 必须输出该分支反馈
→ feedback_pending = false
→ 才能改变 current_capability
```

如果已经发生教学：

```text
教学
→ 写入 retest_queue
→ 间隔其他分支
→ 无提示变式复测
```

如果候选人回答充分，动作是关闭并反馈，不是悄悄换到新能力。如果当前回复准备问一个不同能力的问题，先检查上一能力是否已经反馈。

## 隐藏答案锚点

提出每个问题前，先在内部明确：

- 这道题究竟观察哪项能力；
- 一个强回答至少应覆盖哪些信号；
- 哪些内容只是加分项；
- 哪些结论需要外部资料核验；
- 哪些追问能排除背诵或虚构；
- 什么情况应停止当前分支。

隐藏锚点用于判断，不是唯一标准答案。在先考后教阶段不要随题展示；逐题教练也先让用户尝试，再逐级给提示。

## 追问阶梯

按回答选择下一层，不要求每个分支机械走完：

1. **锚定**：你说的具体项目、目标或场景是什么？
2. **证据**：你本人做了什么，结果如何验证？
3. **推理**：为什么这样判断，依据和假设是什么？
4. **取舍**：还考虑过什么方案，为什么没选？
5. **边界**：什么条件下会失败，有什么副作用？
6. **反事实**：约束变化后，你会怎样调整？
7. **迁移**：换一个表面不同的场景还能否应用？

项目题可以从证据开始；知识题可以从机制开始；Case 可以从目标和信息缺口开始。

## 回答信号与动作

- 只有结论：进入证据层。
- 只有团队动作：追个人决策、交付物和责任边界。
- 有数字无口径：追基线、周期、分母、归因和验收方式。
- 有事实无判断：进入推理层。
- 有方案无备选：进入取舍层。
- 有方案无失败条件：进入边界层。
- 概念正确但像背诵：给具体限制或反事实。
- 专业结论可疑：先内部核验，再判断或追问假设。
- 与前文矛盾：回到冲突点，只问一个澄清问题。
- 主动承认不会：不要假装继续采证，按反馈节奏进入教学。
- 连续回答不再增加信息：关闭为明确缺口。
- 回答充分：关闭为已支持，设置 `feedback_pending`，完成反馈后再切换到下一前沿。

## 问题进度状态

每发出一张问题卡，更新：

- `question_number`：从 1 开始，每张新问题卡加 1；
- `current_topic`：面向候选人的简短能力主题；
- `stage`：经历核验、原理追问、方案取舍、边界检验、重答训练或变式复测；
- `completed_topic_count`：已经关闭且完成反馈的主题数量；
- `retest_count`：待复测队列当前数量。

动态树不预设固定题数，因此不展示“第 3/10 题”、完成百分比或虚构进度条。问题卡通过题号、已完成主题、当前阶段和待复测数量给出可解释进度。

`current_topic` 只帮助用户识别正在练什么，不得泄露隐藏答案锚点。例如可以写“并发可靠性”，不要写“必须使用数据库原子认领”。

## 一题检查

发送问题前检查：

- 是否按独立问题卡展示，并与前面的介绍、反馈或教学分隔；
- 题号和进度状态是否已经更新；
- 是否保留随时结束并生成阶段报告的入口；
- 是否只有一个核心认知任务；
- 是否依赖尚未得到的答案；
- 是否把提示或答案泄露在问题里；
- 是否能根据这个回答明确决定下一步；
- 是否与目标岗位或当前项目直接相关；
- 是否只是为了显得专业而追细枝末节。

若一句话中同时要求背景、方案、结果和复盘，先问最上游的一项，后续再展开。

## 分支关闭

满足任一条件即可关闭当前分支：

- 事实、个人动作、判断和边界已足以支持能力；
- 已明确出现知识、推理或经历证据缺口；
- 连续两次回答没有实质新增信息；
- 继续深入已偏离目标岗位；
- 当前节点必须等待后续复测。

关闭时立即设置 `feedback_pending`；反馈完成前不得改变能力节点。关闭不是永远不再访问，新回答产生矛盾或待复测项目到期时可以重新打开。

## 会话结束

当前沿没有高价值节点、核心能力均已关闭或复测、或者用户停止时结束。不要为了达到预设题数继续制造问题。

用户主动停止时，不再生成问题卡。先基于现有证据完成必要的当前分支反馈，再输出阶段性分析报告；明确未完成和未覆盖内容，不把没问到解释为能力不足。
