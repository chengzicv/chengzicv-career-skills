# 补充追问题库

STAR 补强优先使用 `guided-star-interview.md` 和 `star-option-example-library.md`。本文件只处理五步协议之外的必要缺口：角色边界、数字口径、材料冲突、技能真实性和身份信息。

## 通用规则

1. 一次只问一个问题。
2. 先给 3-6 个可选答案，再给“记不清/跳过”和“愿意补充”。
3. 每题给一个具体短案例，案例匹配岗位，但不得进入事实台账。
4. 用户跳过后使用保守写法，不换个说法继续追问。
5. 能从材料中直接找到的内容不要问用户。
6. 只有用户主动选择“愿意补充”时，才改用开放式问题。

## 角色边界

```text
这段工作里，你承担的范围更接近哪一种？

A. 自己完成一个明确模块或交付物
B. 和其他人共同推进，自己负责其中几步
C. 按安排执行或协助部分工作
D. 主要旁听、学习或体验
E. 记不清，先按保守写法
F. 我愿意补充具体分工

参考案例（仅用于帮助回忆）：
例如同一个活动里，有人负责整体排期，有人只负责社群通知；两者都能写，但动词强度不同。
```

## 已有百分比缺口径

```text
你写到“提升 30%”，这个数字主要指哪类变化？

A. 人数或数量增加
B. 转化率、准确率或通过率提高
C. 时间或成本减少
D. 错误、咨询或返工减少
E. 记不清口径，先删除百分比
F. 我愿意补充原来值、后来值和时间范围

参考案例（仅用于帮助回忆）：
“从每天约 20 次咨询降到 8 次”比单写“减少 60%”更容易解释口径。
```

用户选择 A-D 后，再在同一步补问一次对应单位或前后值；仍记不清则删除数字。

## 技能真实性

```text
这项工具或技能，你实际用到什么程度？

A. 用它独立完成过交付物
B. 在项目中实际操作过，但需要指导
C. 只做过练习或课程作业
D. 只了解概念，没有实际使用
E. 记不清，先不写
F. 我愿意补充使用场景

参考案例（仅用于帮助回忆）：
“用 SQL 提取报名和付费数据”属于项目使用；只看过 SQL 教程则不写成“熟练掌握”。
```

## 材料冲突

冲突问题只展示两个或多个来源中的原说法，不提供带倾向性的推荐答案。

```text
两份材料里的项目时间不同，最终以哪个为准？

A. 2025.03-2025.06
B. 2025.04-2025.07
C. 两个都不对，我愿意补充
D. 记不清，暂不写月份

参考案例（仅用于帮助回忆）：
如果 3 月只是准备、4 月才正式开始，可以补一句“3 月筹备，4 月正式执行”。
```

## 必要身份信息

毕业时间、工作年限、联系方式、求职方向等无法从材料判断且会影响简历分池时，可以直接问；仍保持一次一题，但无需强行套 STAR 进度条。

## 开放式补充的边界

用户选择“我愿意补充”后，给一个最小填空：

- 数字：`原来大约__，后来大约__，用了__时间。`
- 动作：`我先做了__，接着__，最后__。`
- 难点：`最麻烦的是__，因为__。`
- 角色：`团队共__人，我主要做__。`

一次只给一个填空，不要求用户完整写 STAR。
