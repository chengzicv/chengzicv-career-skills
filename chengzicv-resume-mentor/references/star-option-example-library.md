# STAR 选项与连续案例库

按目标岗位选择一章，为五步问题卡生成选项和参考案例。不要整库输出给用户，也不要机械照抄；选项应结合用户材料收窄到 3-6 个。

## 目录

1. 通用生成规则
2. 产品
3. 运营与内容

5. 数据分析

## 1. 通用生成规则

五步各自覆盖以下答案空间：

| 步骤 | 常见选项空间 |
| --- | --- |
| 场景与规模 | 单次/持续、数量、用户/客户/数据/模块、周期、频率、协作范围 |
| 任务与目标 | 效率、质量、增长、体验、交付、合规、成本 |
| 关键难点 | 需求不清、时间紧、资源少、数据乱、技术异常、跨方协作、方案无效、无明显难点 |
| 解决动作 | 拆解、对齐、分析、制作、测试、排查、自动化、复盘、取舍 |
| 结果与数据 | 速度、数量、质量、增长、采用、验收、复用、交付物、无统计 |

每题案例沿用同一个示例项目。示例只承担“答案颗粒度演示”，不能充当用户事实。

## 2. 产品

### 推荐选项

- 场景与规模：需求数、用户反馈数、页面/流程/字段数、迭代周期、协作角色数。
- 任务与目标：解决高频反馈、降低操作阻力、补齐异常流程、按期上线、改善转化。
- 关键难点：需求描述模糊、业务与开发理解不同、边界条件多、时间紧、上线前需求变化。
- 解决动作：归类反馈、画原型、补字段说明、写验收标准、走查、排优先级、跟进联调。
- 结果与数据：上线功能数、反馈覆盖数、缺陷减少、流程步骤变化、按期验收、文档复用。

### 连续参考案例

1. 场景：某产品实习生整理 20 条登录相关反馈，涉及登录失败、验证码和页面跳转 3 类问题。
2. 目标：团队希望在下一次迭代前找出最影响登录完成率的问题，而不是把 20 条反馈逐条开发。
3. 难点：同一问题被用户用不同说法描述，业务和开发对“登录失败”的范围理解也不一致。
4. 动作：她先归类反馈，再用 Axure 补异常提示原型，并和开发逐项确认字段校验与验收标准。
5. 结果：3 类高频问题进入迭代，原型和字段说明通过走查；没有转化数据时只写交付与覆盖范围。

## 3. 运营与内容

### 推荐选项

- 场景与规模：社群数、用户数、内容篇数、活动场次、渠道数、运营周期、发布频率。
- 任务与目标：报名、到课、转化、活跃、留存、咨询量、内容产出、按期活动交付。
- 关键难点：消息被淹没、用户分层差异、渠道数据分散、时间紧、素材不足、原话术效果差。
- 解决动作：整理 FAQ、调整提醒节点、对比渠道、用户分层、修改标题/话术、排期、复盘数据。
- 结果与数据：报名/到课前后值、咨询量变化、内容数量、阅读/互动、活动交付、SOP 复用。

### 连续参考案例

1. 场景：某运营实习生同时维护 3 个求职社群，每个群约 200 人，并跟进每周一次的直播活动。
2. 目标：活动前关于时间和入口的重复咨询很多，她需要减少重复回复并保证用户按时到场。
3. 难点：多提醒会打扰用户，少提醒又容易错过；不同群的活跃时间也不一样。
4. 动作：她整理一周高频问题做成 FAQ，并把提醒调整到前一天和开始前 1 小时，记录各群咨询情况。
5. 结果：重复咨询从每天约 20 次降到 8 次，FAQ 后续继续用于新群运营。

## 4. 技术与 AI 工程

### 推荐选项

- 场景与规模：接口/页面/模块数、数据量、请求量、用户量、开发周期、协作端数。
- 任务与目标：实现功能、修复异常、提升响应、降低错误、完成部署、保证兼容或稳定。
- 关键难点：难复现、日志不足、边界条件多、第三方接口不稳定、性能瓶颈、前后端口径不一致。
- 解决动作：复现、加日志、拆链路、写测试、对比方案、缓存、降级、联调、部署、回滚。
- 结果与数据：响应时间、错误率、通过用例数、接口/模块交付数、上线/演示/验收、故障恢复时间。

### 连续参考案例

1. 场景：某开发实习生负责简历保存和查询 2 个接口，并与前端联调登录后的保存流程。
2. 目标：解决部分用户登录一段时间后保存失败的问题，保证简历内容能够正常提交。
3. 难点：问题不是每次出现，本地难以复现；前端只看到 401，无法判断是鉴权还是请求参数问题。
4. 动作：他补充鉴权日志，按 token 生成、过期和刷新拆链路排查，定位到过期后未触发刷新，并和前端联调修复。
5. 结果：修复方案通过登录过期场景测试并随版本上线；没有错误率数据时只写测试和上线事实。

### AI 项目变体

1. 场景：某 AI 项目成员整理 100 条测试问题，用于评估知识库回答的准确性和引用完整度。
2. 目标：找出回答看似合理但引用错文档的问题，而不是只判断答案是否流畅。
3. 难点：同一问题可能命中多个文档，人工判断标准不一致。
4. 动作：他统一测试标签，对比不同切分长度和 prompt，记录无引用、错引用和答非所问三类错误。
5. 结果：形成可复用的测试集和错误清单，支持后续调整切分与检索参数。

## 5. 数据分析

### 推荐选项

- 场景与规模：数据行数、来源数、指标数、报表数、分析周期、更新频率。
- 任务与目标：发现异常、比较渠道、统计漏斗、减少手工整理、支持排期或投放决策。
- 关键难点：字段不一致、缺失值、重复数据、口径冲突、样本少、结论难解释。
- 解决动作：清洗、去重、统一口径、SQL 查询、透视表、分组对比、异常排查、可视化。
- 结果与数据：处理时长、报表更新频率、异常数、支持的决策、自动化覆盖、交付报表。

### 连续参考案例

1. 场景：某数据实习生每周整理 3 个渠道的报名、到课和付费数据，共涉及 6 个核心指标。
2. 目标：比较不同渠道的实际转化质量，为下一轮活动分配资源提供依据。
3. 难点：三个渠道的用户标识和日期格式不同，直接汇总会出现重复计算。
4. 动作：她用 SQL 提取明细，在 Excel 中统一字段并去重，再用透视表按渠道对比漏斗。
5. 结果：发现社群渠道到课率更高，分析结果用于调整下一轮预热重点；没有投放增幅时不编增长数据。

## 6. 财务、审计与职能

### 推荐选项

- 场景与规模：发票/凭证/合同/账户数、金额量级、核对周期、组织范围。
- 任务与目标：保证准确、找差异、按期结账、完成底稿、减少漏项、满足合规要求。
- 关键难点：材料缺失、口径不同、数据量大、截止期紧、跨部门催收、历史记录不清。
- 解决动作：VLOOKUP/SUMIF、抽凭、勾稽、差异清单、台账、复核、资料清单、节点提醒。
- 结果与数据：核对数量、差异项、按期完成、0 差错、底稿/台账交付、复核通过。

### 连续参考案例

1. 场景：某财务实习生月末核对 300 余条账单记录，涉及总账、明细账和业务台账 3 类材料。
2. 目标：在结账前找出金额或状态不一致的记录，整理给主管复核。
3. 难点：三份表的客户名称写法不同，直接匹配会漏掉同一客户的多种名称。
4. 动作：她先统一客户名称，用 VLOOKUP 和 SUMIF 核对金额，再把无法匹配的记录整理成差异清单。
5. 结果：按期完成 300 余条核对并提交差异清单；若无差错率，只写覆盖量和交付物。

## 7. 招聘与 HR

### 推荐选项

- 场景与规模：岗位数、候选人数、沟通量、面试场次、招聘周期、岗位族。
- 任务与目标：补充人才池、提高到面、缩短流程、校准画像、减少爽约、完成入职。
- 关键难点：画像模糊、回复率低、候选人流失、面试官时间冲突、数据分散、岗位变化。
- 解决动作：拆 JD、建立筛选条件、调整沟通话术、分层跟进、维护漏斗、协调排期、复盘渠道。
- 结果与数据：推荐/到面/offer/入职数量、回复率、周期、人才池规模、流程完成率、招聘台账。

### 连续参考案例

1. 场景：某招聘实习生同时支持 4 个技术岗位，每周沟通约 80 名候选人。
2. 目标：提高有效回复和到面数量，并让用人经理更快判断候选人是否匹配。
3. 难点：最初 JD 只有技术名词，候选人的项目方向与岗位实际业务经常对不上。
4. 动作：她和用人经理确认必选与可放宽条件，重写首轮沟通话术，并按岗位维护推荐与到面漏斗。
5. 结果：形成 4 个岗位的筛选要点和候选人台账；若无转化提升数据，只写沟通量、到面数和交付物。

## 8. 销售与客户成功

### 推荐选项

- 场景与规模：客户/线索数、客单价、区域、跟进周期、产品数、续费节点。
- 任务与目标：获客、转化、回款、续费、激活、问题解决、客户满意或交付。
- 关键难点：需求不清、决策链长、预算有限、异议多、回款延迟、使用率低。
- 解决动作：需求访谈、客户分层、方案演示、异议记录、节点跟进、使用培训、问题清单。
- 结果与数据：成交/续费/回款、转化周期、客户覆盖、问题关闭、使用率、案例沉淀。

### 连续参考案例

1. 场景：某销售助理每周跟进约 30 条企业线索，记录需求、预算和下一次沟通节点。
2. 目标：减少线索长期无人跟进，并帮助销售优先处理意向更明确的客户。
3. 难点：客户回复分散在微信、电话和表格中，历史承诺和下一步动作容易遗漏。
4. 动作：她按意向和预计时间给线索分层，统一记录异议与跟进日期，每天提醒即将到期的节点。
5. 结果：30 条线索都有明确状态和下一步安排；无成交归因时只写覆盖范围与流程交付。

## 9. 项目管理与行政

### 推荐选项

- 场景与规模：项目/部门/供应商数、节点数、资料量、会议频率、周期。
- 任务与目标：按期推进、资料齐全、职责明确、风险可见、会议行动落地、流程规范。
- 关键难点：责任人不清、需求变化、资源冲突、资料迟交、信息不同步、跨部门依赖。
- 解决动作：排期、责任矩阵、会议纪要、风险清单、资料清单、节点提醒、SOP、升级沟通。
- 结果与数据：节点按期率、延期减少、资料完整、项目交付、流程复用、问题关闭数量。

### 连续参考案例

1. 场景：某项目助理跟进 4 个部门的 12 项上线准备任务，每周更新一次进度表。
2. 目标：在上线前补齐资料、培训和测试节点，避免最后一周集中返工。
3. 难点：不同部门使用各自的表格，负责人和截止时间经常不一致。
4. 动作：她统一任务清单，标明责任人、依赖项和截止日期，在周会上逐项更新风险。
5. 结果：12 项准备任务均在上线前关闭，清单后续复用于下一次项目。

## 10. 数字与量级词库

先根据岗位选择单位，再生成选项。不要把词库中的数字直接给用户认领。

| 维度 | 常见单位 |
| --- | --- |
| 工作量 | 条、份、个、次、页、接口、模块、活动、合同、候选人 |
| 覆盖范围 | 用户、客户、社群、渠道、城市、部门、团队、系统 |
| 时间 | 分钟、小时、天、周、月、迭代、结账周期 |
| 频率 | 每天、每周、每月、每次活动、每个版本 |
| 质量 | 错误、遗漏、异常、通过率、准确率、返工次数 |
| 效率 | 原耗时/现耗时、处理量、响应时间、交付周期 |
| 业务结果 | 报名、到课、转化、成交、续费、回款、留存 |

量级表述必须与用户答案一致：

- 精确值：`20 条`。
- 约数：`约 200 人`。
- 区间：`2-5 个模块`。
- 量级：`数十名候选人`、`数百条记录`。
- 无统计：写交付物或完成情况，不使用“显著提升”。
