# 岗位能力证据卡与追问预演

岗位能力证据卡把简历中的强 bullet 映射成“这段经历证明候选人的哪项能力”。它不是故事编号，也不是让用户背答案的台词本。

每张卡同时回答四个问题：

1. 对应简历中的哪段内容？
2. 证明哪项通用能力？
3. 证明哪项岗位专业能力或行业能力？
4. 面试官连续追问时，有哪些“已确认”事实可以回答？

## 哪些 bullet 必须建卡

满足任一条件即建卡：

- 有具体数字、比例、金额、人数或周期。
- 使用负责、主导、搭建、设计、从 0 到 1 等强动词。
- 是候选人的独特卖点或岗位核心证据。
- 面试官很可能追问角色边界、方法、取舍或结果口径。

一份简历一般 4-8 张。不要给普通职责逐条建卡。

## 通用能力维度

与橙子企业初筛面试官对齐，按证据选择 1-2 项，不凑满：

| 维度 | 判断重点 |
| --- | --- |
| 岗位/组织匹配与动机 | 为什么选择岗位和组织，选择是否自洽 |
| 行为证据与真实性 | 是否说清案例、个人贡献、结果和边界 |
| 责任心与交付可靠性 | 是否重视质量、期限、异常和交接 |
| 学习能力与复盘成长 | 是否根据新任务、失败和反馈改变做法 |
| 沟通协作与人际处理 | 是否对齐目标、处理分歧并推进共识 |
| 问题分析与业务判断 | 是否拆解目标、约束、选项、指标和风险 |
| 计划组织与推进执行 | 是否安排关键路径、资源、责任人和验收 |
| 应变抗压与情绪稳定 | 变化和压力下能否先止损、再处理、后复盘 |
| 职业成熟度、规则意识与边界感 | 是否现实处理流程、权限、合规和职业边界 |
| 表达清晰度与自然度 | 是否先给重点，再自然讲清证据 |

## 岗位专业能力维度

岗位专业能力不使用固定词表。先拆 JD 的业务目标、核心任务、工具方法、行业场景和交付物，再为卡片选择 1-2 项。

常见示例：

### 技术岗

- 技术栈与工程实现
- 问题排查与质量保障
- 系统/业务场景理解
- 接口联调与工程协作
- 性能、安全、测试或部署
- 所在行业的产品与用户理解

### 招聘与 HR 岗

- 岗位理解与人才画像
- 寻访、筛选与初筛判断
- 候选人沟通与流程管理
- 面试协调与用人经理协作
- 招聘漏斗与数据复盘
- 用工规则、隐私与合规意识
- 所招聘行业与岗位族理解

### 产品、运营、销售等业务岗

- 行业与业务模式理解
- 用户/客户需求判断
- 产品、内容、活动或销售方法
- 数据指标与业务复盘
- 跨部门推进与交付
- 渠道、增长或客户经营

### 财务、法务、行政、采购、制造等职能岗

- 行业规则与业务流程
- 专业工具、制度或标准
- 风险识别与合规控制
- 台账、报表、合同、图纸或 SOP 交付
- 跨部门资料和节点管理

## 卡片命名

人类可读标题使用：

```text
通用能力维度｜岗位专业能力｜对应经历
```

示例：

- `问题分析与业务判断｜AI 工程稳定性｜复盘旁白异常降级`
- `责任心与交付可靠性｜前端工程交付｜互动绘本课程`
- `沟通协作与人际处理｜技术岗位需求校准｜前端招聘方案`
- `学习能力与复盘成长｜行业理解｜从前端开发转向技术招聘`

如果标题过长，可以省略岗位专业能力，但不能只写内部编号。人类可读交付中禁止使用 `story_S01`、`card_01` 作为标题。

## 卡片格式

```text
### 问题分析与业务判断｜AI 工程稳定性｜复盘旁白异常降级

对应简历：实习经历 · AI 复盘旁白 · 第 2 条

能力结论：这段经历证明候选人能识别异常链路、区分风险优先级并设计降级处理。

通用能力证据：
- 问题分析与业务判断：...
- 责任心与交付可靠性：...

岗位专业能力证据：
- AI 应用工作流理解：...
- 前端异常处理：...

事实证据链：
- 情境：...
- 任务：...
- 动作：...
- 结果：...

30 秒讲法：...

面试官可能追问：
1. 动作细节 → 回答要点：...
2. 结果/数字口径 → 回答要点：...
3. 角色边界 → 回答要点：...

证据缺口：无 / 具体缺口
事实引用：事实编号列表
```

## 正向：能力证据深挖

使用 `guided-star-interview.md` 的五步选择式补强：

1. 场景与规模：发生在哪里，涉及多大范围。
2. 任务与目标：为什么这件事重要。
3. 关键难点：遇到哪些约束、冲突或取舍。
4. 解决动作：本人具体做了什么、用了什么工具。
5. 结果与数据：如何验证，产生了什么变化或交付物。

每次只问一个问题，并从 `star-option-example-library.md` 选择同岗位案例帮助用户回忆。

把每层内容拆成事实进入台账。卡片只能引用“已确认”事实；“待验证”或“推断”内容必须先确认。

## 反向：追问预演

每张卡至少跑三问：

```text
追问 1（动作细节）：第一步做了什么，随后怎么推进？
追问 2（结果口径）：结果怎么验证，数字如何计算？
追问 3（角色边界）：哪些是本人完成，哪些由团队或主管完成？
```

判定：

- 三问都有“已确认”事实 → 通过。
- 一问答不上 → 补证据；补不了就同步降级简历 bullet。
- 能讲过程但没有取舍 → 写执行型能力，不强写问题判断或主导能力。
- 只有岗位术语、没有行为证据 → 不能认定岗位专业能力。

## 交付规则

- 岗位能力证据卡放在内部“简历优化交付”文档，不进入外发简历或作品集。
- 卡片标题与最终简历 bullet 一一对应；bullet 改动后同步更新卡片。
- 证据缺口同步进入内部确认清单。
- 工作样本与面试培训可以复用卡片的“30 秒讲法”和追问，但不要让用户机械背诵。

## 常见错误

| 错误 | 纠正 |
| --- | --- |
| 用 `story_S01` 作为标题 | 改成“能力维度｜岗位专业能力｜对应经历” |
| 只写 STAR，不说明证明什么 | 先写能力结论，再放事实证据链 |
| 把“台词本”当能力证据 | 台词只是表达层，卡片核心是事实与能力映射 |
| 通用能力堆满十项 | 每张卡只选有证据的 1-2 项 |
| 岗位专业能力照抄 JD | 必须有工具、动作、场景或交付物证据 |
| 预演失败只删卡 | 同步降级或删除简历 bullet |
