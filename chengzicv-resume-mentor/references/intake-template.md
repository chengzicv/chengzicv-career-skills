# 材料接收模板

用于处理用户一次性塞进来的多份文档、简历、JD、反馈和补充信息。

## 材料分类

先把材料分成这些类别：

```text
原始简历：用户最早版本，优先作为事实来源。
修改版简历：用户或别人改过的版本，可作为表达参考，也可能有过度包装。
目标JD：优化方向，不是事实来源。
补充说明：用户额外提供的事实，通常很有价值。
用户反馈：用户想强调或不想强调的点。
顾问建议：修改方向，不等于用户事实。
作品/项目材料：可作为事实证据，但要提炼。
聊天记录：可挖事实，但要避免误读。
面试反馈/挂经：高价值输入。面试官追问什么、用户哪里答不上来，直接暴露简历的高风险 bullet 和能力证据缺口，用于反推降级和岗位能力证据卡补强。
```

## 材料编号格式

建议内部使用。“优先级”对应 `workflow.md` 材料优先级列表的序号，数字越小事实优先级越高；JD 不是事实来源，不参与事实优先级，“优先级”填 0。面向用户展示时使用“来源1、来源2”的中文连续编号：

```json
{
  "材料": [
    {
      "编号": "来源1",
      "类型": "原始简历",
      "标题": "原版简历",
      "优先级": 3,
      "备注": "事实基础"
    },
    {
      "编号": "来源2",
      "类型": "目标岗位JD",
      "标题": "目标岗位JD",
      "优先级": 0,
      "备注": "优化方向，不作为用户事实"
    }
  ]
}
```

## 信息冲突处理

如果两份材料冲突：

- 时间冲突：不要擅自合并，列为待确认。
- 职位冲突：优先使用用户最新确认版本。
- 数据冲突：保守使用较低或更可解释的数据，或列为待确认。
- 动词强度冲突：优先使用更保守动词。
- 技术栈冲突：只有至少一份材料明确出现才可写。

## 缺信息时怎么处理

缺信息不等于不能写。可以这样处理：

| 缺口 | 处理 |
| --- | --- |
| 缺结果数字 | 写交付物、覆盖范围、完成情况，不编数据 |
| 缺工具 | 如果行业常识明显，可问用户确认，不直接写 |
| 缺角色边界 | 用参与、协助、支持、配合等保守动词 |
| 缺项目背景 | 从原文对象和目标推导轻量背景，不新增业务事实 |
| 缺目标岗位 | 先按用户简历最强方向给 2-3 个投递方向 |

## 用户输入模板

如果需要让用户以后按模板给材料，可以给这个：

```text
【目标岗位 / JD】
粘贴目标岗位 JD，或者写目标岗位名称。

【原始简历】
粘贴当前简历全文。

【补充信息】
补充你没写进简历但真实做过的事，比如工具、流程、数据、项目背景、团队规模、交付物。

【你想强调的方向】
比如技术能力、业务理解、转行匹配、项目经验、稳定性、沟通协作。

【你不想写或不能写的内容】
比如不想夸大、不想写某段经历、某些数据不能确认。
```

## 顾问内部记录模板

处理材料时可以先在回答里简短列出：

```text
我先按这些材料理解：
- 来源1：原版简历，作为事实基础
- 来源2：JD，作为优化方向
- 来源3：补充说明，作为事实补充

我会保守处理：
- 未确认数据不写死
- 顾问建议只作为表达方向
- 技术栈只写原文出现过或用户确认过的
```
