# JD 能力模型

JD 不是关键词仓库。要拆出企业为什么招这个人，以及用户经历怎么证明能上手。

## 拆 JD 的顺序

1. 目标岗位名称
2. 行业和业务场景
3. 硬性条件
4. HR 初筛关键词
5. 业务/技术负责人关心的能力
6. 招聘方可能担心的风险
7. 用户简历可迁移证据
8. 可验证交付物
9. 明显差距和补救策略

## 输出结构

```text
【目标岗位】
AI产品经理 / 后端开发 / 数据分析师 / 运营 / 财务 / 审计等

【岗位要解决的问题】
- 企业招这个人来做什么
- 入职后最可能先接什么任务

【HR会搜的词】
- 工具、技术、证书、行业词、岗位词

【业务负责人会看的证据】
- 项目、指标、流程、技术深度、交付物

【招聘方可能担心的风险】
- 对学生/初级/转岗候选人，判断企业可能担心学历、稳定性、项目同质化、只会工具不会交付、层级过高或方向不聚焦等问题

【用户已有匹配证据】
- 哪些经历能证明这些能力

【可验证交付物】
- 作品集、Demo、源码、接口文档、测试记录、部署说明、工程图、BOM、SOP、台账、复盘表等可让招聘方快速判断的材料

【差距】
- 哪些点简历里没有，不能硬写
```

## 匹配度战略

简历不是“用户会什么”的清单，而是给企业一个理由：

```text
这个人来以后，可以比较快地接住目标岗位的核心任务。
```

所以所有优化都服务于：

- 让 HR 看到硬关键词。
- 让业务负责人看到具体场景和动作。
- 让用户面试时能顺着简历讲出细节。

## 三个视角

### 视角转换

不要站在用户角度罗列“我做过什么”，要站在企业角度证明：

```text
我能解决你这个岗位现在要解决的问题。
```

简历是“送礼”，要送企业想要的东西，不是把用户所有东西都摆上去。无关经历宁可压缩，也不要抢占最强匹配点的位置。

### 垂直专家思维

优先挖用户在目标行业、目标岗位、目标业务场景下的经验。

哪怕只是参与，也要写清楚：

- 参与的是哪个具体场景。
- 接触了什么真实流程。
- 用过什么工具或方法。
- 这段经验怎么迁移到目标岗位。

高价值简历不是“我很全面”，而是“我在某类问题上已经有可复制经验”。

### 打通筛选环节

简历要同时过两关：

- HR：关键词、学历、年限、岗位名、工具名、行业词。
- 业务/技术负责人：场景理解、具体动作、交付物、技术或业务细节。

只堆关键词，业务看不出能力。只写技术细节，HR 可能看不懂。要把两者接起来。具体改写校验见 `dual-reader-rewrite.md`。

## 国内平台关键词逻辑

Boss 直聘、猎聘、智联等平台的筛选是「HR 关键词搜索 + 人工 30 秒初筛」，不是欧美式 ATS 机器解析。规则：

- 岗位名同义词都要覆盖：JD 写"产品经理"，用户经历里是"产品实习生"，求职意向和经历标题要能被"产品"搜到。常见同义对：运营/新媒体运营/用户运营、Java开发/后端开发、数据分析/商业分析。
- 技能词用 JD 的原词写法。JD 写"SQL"就写"SQL"，不要只写"数据库查询"；JD 写"Python"不要只写"编程"。
- 全称和常用缩写在简历里至少各出现一次：如 "Spring Boot"、"PRD（产品需求文档）"，视 JD 用词决定。
- 硬关键词要出现在三个位置至少之一：求职意向行、专业技能、至少 1 条经历 bullet。只堆在技能栏而经历里无对应动作，业务负责人会判定为凑词。
- 不追求关键词密度。国内没有 ATS 密度算法，同一个词硬塞 3 次以上反而显得刻意。
- 用户没用过的技术，JD 再想要也不能加。这是禁止项，不是技巧。

## 能力模型示例

### 产品岗

常见能力：

- 需求分析
- 用户调研
- 竞品分析
- 原型 / PRD
- 数据复盘
- 跨部门沟通
- 版本迭代

简历写法要落地：

- 不写“具备产品思维”
- 写“用 Axure 画原型，整理 12 条用户反馈，和开发对齐字段和交互边界”

### 运营岗

常见能力：

- 内容生产
- 活动执行
- 用户增长
- 社群维护
- 数据复盘
- 渠道投放
- 转化漏斗

简历写法要落地：

- 不写“负责用户增长”
- 写“统计小红书、社群、朋友圈 3 个渠道的报名转化，调整标题和发布时间”

### 技术岗

常见能力：

- 技术栈匹配
- 工程实现
- 问题排查
- 性能优化
- 接口设计
- 部署运维
- 协作联调

简历写法要落地：

- 不写“熟悉后端开发”
- 写“用 Spring Boot 写用户登录接口，接入 JWT 鉴权，和前端联调登录态刷新问题”

### 数据分析岗

常见能力：

- SQL
- Excel
- Python / Pandas
- 指标体系
- 可视化
- 业务解释
- 复盘建议

简历写法要落地：

- 不写“数据驱动”
- 写“用 SQL 拉取订单和用户行为数据，用 Excel 透视表拆出渠道转化差异”

### 财务 / 审计 / 职能岗

常见能力：

- 对账
- 台账
- Excel 函数
- 凭证 / 发票 / 报表
- 流程梳理
- 合规检查
- 跨部门资料收集

简历写法要落地：

- 不写“严谨细致”
- 写“用 VLOOKUP、SUMIF 核对总账、明细账和报表差异，整理异常清单给主管复核”

## 差距处理

差距不能靠编。只能：

1. 用相近经历迁移。
2. 把弱相关经历压缩。
3. 通过追问寻找真实证据。
4. 在投递方向上给更适合的岗位建议。

示例：

```text
JD 要 SQL，但用户材料没出现 SQL。
不能写：熟练使用 SQL。
可以问：你有没有用过 SQL、Excel 透视表、Python 或其他工具做过数据整理？
如果用户没有：技能模块不写 SQL，改写已有 Excel 或数据整理经历。
```
