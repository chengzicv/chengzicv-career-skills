# 多文档交付与 Diff 标准

本文件规定如何按受众拆分交付。核心：内部材料保留判断过程，外发材料只保留招聘方应该看到的成品。

## 默认文件包

包含简历与作品集的完整任务默认交付四个 Markdown 文件：

| 文件 | 受众 | 内容 |
| --- | --- | --- |
| `姓名-目标岗位-简历优化交付.md` | 用户/顾问内部 | 策略、确认项、diff、岗位能力证据卡、事实台账、风险提醒、后续补强 |
| `姓名-目标岗位-完整版简历.md` | 招聘方/面试官 | 干净、可直接复制投递的完整简历 |
| `姓名-目标岗位-作品集.md` | 招聘方/面试官 | 作品正文、方案案例、模板、方法和可验证交付物 |
| `姓名-目标岗位-工作样本与面试培训.md` | 用户内部 | 经历背景、流程细节、案例逻辑、追问训练、证据缺口和练习 |

只做简历时交付前两份。局部改写时交付“优化交付 + 干净简历/模块”两份。用户明确不需要某类文件时可省略。

默认只创建 Markdown。用户明确指定 DOCX/PDF 等格式时，再从对应外发或内部 Markdown 转换，仍保持受众边界。

## 1. 简历优化交付文档（内部）

推荐结构：

```text
# 一、这份简历的打法
# 二、需要确认的点
# 三、主要改动（diff）
# 四、岗位能力证据卡
# 五、事实台账
# 六、风险提醒与补强建议
```

这里可以出现：

- `[待确认]`、证据缺口、禁用事实。
- “事实1”“来源1”等中文编号和原文对照。
- 动词降级、数字口径和背景调查风险。
- “完成后启用”“不建议写”等顾问判断。

不要把这份文件当简历发送给招聘方。

### Diff 格式

```text
【经历X · 改动#N】

原文：
> 一字不差贴原文

改后：
> 新版本

对齐 JD：具体条件 / 关键词 / 风险缓解
依据事实：事实编号或原文出处
风险等级：无 / 需用户确认 / 已降级处理
```

规则：

- 轻微统稿可合并说明；事实表达、动词强度和数字变化必须单独出 diff。
- “需用户确认”同步进入内部确认清单和相关岗位能力证据卡。
- 预演失败时同步降级外发简历 bullet，不能只在内部标风险。

## 2. 完整版简历（外发）

推荐结构：

```text
姓名
电话 | 邮箱 | 城市 | 链接（可选）
期望岗位 | 身份标签

个人优势
教育背景
工作/实习经历
项目经历
校园经历（相关且真实时）
专业技能
```

必须满足：

- 可以整份复制给招聘方，不需要用户再次删除顾问文字。
- 只含“已确认”事实；“待验证”内容只有在保守表述仍准确时才可使用。
- 没有内部说明、确认项、风险、来源、岗位能力证据卡、练习或免责声明。
- 没有方括号占位、模板变量、注释或“完成后启用”。
- 无法确认的内容直接删除，不能只删除风险提示后保留主张。

### 外发简历禁泄漏词

交付前搜索：

```text
[待确认]
需确认
需用户确认
风险等级
事实引用
事实编号
来源编号
岗位能力证据卡
使用提醒
建议补充
完成后启用
不可投递
模拟数据
编造
顾问
```

如果这些词是候选人真实作品名的一部分，人工判断；其他情况一律移出外发简历。

## 3. 作品集（外发）

作品集只在有作品、方法案例或用户明确要求时生成。推荐结构：

```text
# 封面与定位
# 行业/岗位理解
# 作品一：...
# 作品二：...
# 方法与模板
# 数据口径或复盘（有真实/示例数据时）
```

外发作品集规则：

- 不放顾问提示、风险提醒、事实台账、培训说明、证据缺口或大段真实性声明。
- 实际完成的项目按真实项目写，并保留可验证交付物。
- 非实际业务内容写成“岗位招聘方案案例”“候选人示例”“漏斗示例”或“研究项目”，不写成公司任职、真实候选人、真实录用或客户业绩。
- 示例数据只用于解释方法，标题或字段中就地写清“示例”；不要用醒目警告破坏作品阅读，也不要删除示例属性冒充真实结果。
- 不展示真实候选人的姓名、电话、邮箱、头像、身份证或完整私人聊天。
- 如果一个内容只有伪装成业绩才显得有价值，删除它或改成可验证的方法/模板交付物。

## 4. 工作样本与面试培训（内部）

推荐结构：

```text
# 一、简历和作品集内容地图
# 二、每段经历的背景与角色边界
# 三、操作流程和交付物讲解
# 四、面试官可能追问与回答要点
# 五、仍需补证据的地方
# 六、练习任务与复盘方法
```

这份文件用于让用户真正掌握内容，而不是背统一口径：

- 解释简历 bullet 来自哪些“已确认”事实。
- 把流程、工具、角色边界、数字口径和取舍讲清楚。
- 给出追问和回答要点；缺证据就提示补证据或降级简历。
- 对作品方案说明为什么这样设计、哪些是示例、面试时如何准确称呼。
- 不生成虚假时间线、虚假同事/候选人、伪造数据口径或规避背调的话术。

## 受众隔离审查

四份文件生成后分别检查，不从一个总文档机械切割：

### 内部文档

- 是否保留关键确认项、证据缺口和风险？
- 岗位能力证据卡是否与最终简历 bullet 一致，且标题能直接看出证明的能力维度和对应经历？
- 用户是否知道哪些内容不能外发？

### 外发简历

- 是否通过“禁泄漏词”搜索？
- 是否存在无证据数字、未来计划或模拟任职？
- 删除内部提示后，相关主张是否仍然成立？不成立就整条删除。

### 外发作品集

- 是否只有作品正文与必要方法说明？
- 示例是否局部准确标识，但没有大段免责声明？
- 是否没有把方案案例写成任职或业绩？
- 是否完成候选人隐私脱敏？

### 内部培训

- 是否能帮助用户解释真实事实、方法和边界？
- 是否同步了外发文件的最终版本？
- 是否没有教授欺骗或规避核验？

## 输出语气

内部文件像顾问交付：直接、透明、说清风险。外发文件像候选人作品：简洁、专业、没有顾问腔。

## 工程化输出

用户明确要求工程化对接时，可按 `resume-schema.md` 输出 JSON，并用 `audience` 区分：

```json
{
  "internal_delivery": {},
  "external_resume": {},
  "external_portfolio": {},
  "internal_training": {}
}
```

不要同时默认输出 Markdown 与 JSON 两套；按用户要求选择格式。
