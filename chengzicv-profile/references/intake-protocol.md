# 零材料求职建档协议

## 目录

- 开始前判断
- 材料优先路径
- 零材料路径
- 快速填空与经历雷达
- 更新与冲突
- 暂停、保存与恢复
- 转交

## 开始前判断

先读取当前对话，识别用户已经提供的材料、背景、目标和期限。不要因为触发本 Skill 就要求用户重述。

按下面顺序决定第一步：

1. 已有文件或文字材料：先提取，不能先发长表单。
2. 已有清楚背景但无文件：先生成小型档案快照，再只问一个关键缺口。
3. 完全零材料：只收集当前身份与最着急的问题。
4. 只要空白模板：直接复制对应 Asset，不要求先交个人信息。
5. 要暂停或总结：立即交付快照，不继续 intake。

## 材料优先路径

用户可以提供旧简历、Word/PDF、PPT、大作业、奖状、证书、截图、作品链接、项目记录、投递记录或面试反馈。

收到材料后：

1. 编号并说明每份材料属于什么；
2. 提取材料直接支持的事实；
3. 把模板文字、他人经历、教师要求和用户事实分开；
4. 标出冲突和无法确认的内容；
5. 先输出第一版档案快照；
6. 只有一个缺口会明显改变档案或下一步时，才追加一个问题。

不要要求用户先把文件转成统一格式。宿主能够读取就直接处理；不能读取时给出粘贴文字、截图或导出 PDF 的具体回退。

## 零材料路径

用户说“没有简历、没有经历、什么都没有”时，不接受这个结论作为事实。先从容易回答的背景开始：

```text
先从一句话开始就行：
你现在读什么专业、预计什么时候毕业，以及最近最着急解决的求职问题是什么？

不确定的地方直接写“不确定”。
```

收到回答后先生成小型档案，再选择一个最有信息价值的板块。默认优先级：

```text
当前期限和求职阶段
→ 教育背景
→ 至少一段经历素材
→ 目标岗位或待判断方向
→ 证书奖项与其他材料
```

期限可以改变顺序。已经临近投递或面试时，只补当前交接所需的最少档案。

## 快速填空与经历雷达

简单事实可以用一张快速填空卡成组收集：

```text
教育信息先记这几项，知道多少填多少：

- 学校 / 学历 / 专业：
- 入学时间 / 预计毕业时间：
- GPA、排名或主要课程（没有可跳过）：
- 四六级、技能证书或奖项（没有可跳过）：
```

不得连续发送多个板块。用户回答后先更新档案，再决定下一个板块。

用户想不到经历时，使用识别式经历雷达：

```text
下面哪类事情你做过？可多选，回复字母即可。

A. 课程大作业、实验、论文、答辩或小组项目
B. 竞赛、奖项、训练营或证书实践
C. 社团、学生会、班级、活动组织或志愿服务
D. 兼职、副业、家教、销售、客服或内容运营
E. 写代码、做网页、分析数据、做设计或使用 AI 工具
F. 帮老师、同学或组织整理资料、沟通协调、排期和交付
G. 暂时想不到
```

用户选择后只追问其中最有希望的一类：

```text
这件事叫什么、发生在什么时候？你当时是什么角色？
```

后续按任务、动作、结果/交付物和证据一次推进一个缺口。不要直接启动完整 STAR 访谈；需要岗位化补强时交给 `chengzicv-resume`。

## 更新与冲突

用户补充或修改信息时：

- 先明确本轮新增或修正的字段；
- 新信息与旧信息冲突时保留两者和来源，请用户确认；
- 用户要求删除时，从当前快照中移除并说明已不再保留；
- 不因为一个字段变更重问整个板块；
- 用户给出一串信息时一次吸收，不机械拆成多轮确认。

简短回显格式：

```text
已更新：六级（CET-6），获得时间改为 2025 年 12 月。
仍待确认：是否需要把分数写进外发简历。
```

## 暂停、保存与恢复

用户说“暂停、退出、先到这里、总结现状”时：

1. 立即停止提问；
2. 按 `profile-schema.md` 输出阶段快照；
3. 列出已接收材料和最关键待确认项；
4. 给一句继续时可直接复制的承接语。

普通聊天不得声称自动跨会话保存。需要持久化时：

- 产品 Runtime 已明确提供存储：遵守其数据政策与注入状态；
- 用户明确要求写文件：先确认目标文件和位置，再保存；
- 无持久化能力：把完整快照交给用户复制、下载或下次重新上传。

任何真实档案都不得保存到 ChengziCV Skill 目录、开发 Evals、公开仓库或示例资产中。

恢复时只使用当前对话可见历史、用户带回的快照或 Runtime 明确注入的档案。先回显恢复到的版本与关键目标，再继续一个板块。

## 转交

转交前输出一段简短说明：

```text
这份档案已经足够支持下一步：[下一步名称]。
我会带上：[已确认材料与关键事实]。
仍待确认：[只列会影响下一步的缺口]。
```

目标不清且需要做职业判断时转 `chengzicv-career`；目标或 JD 明确、需要产出简历时转 `chengzicv-resume`。不要在建档阶段提前替用户决定岗位，也不要把空白字段包装成完整简历。
