# 教学案例到真实简历的实践准入门

## 何时读取

面向大三、大四、校招或缺少实习经历的学生提供教学案例，生成学生可执行项目，或有人希望把案例、岗位练习、仿真项目写进真实简历时读取。`chengzicv-resume` 与 `chengzicv-case-factory` 共用本文件；其他文件只能补充，不能放宽这里的真实性门槛。

## 一、核心原则

教学案例解决“高质量材料长什么样”，不能自动成为学生经历。只有学生亲自执行并留下可核验工作证据的部分，才能转成真实简历。

```text
教学参考
→ 可执行任务
→ 学生亲自完成
→ 留下过程证据
→ 核验边界与追问
→ 转成个人项目简历
```

如果一段内容需要候选人在面试中假装任职、比赛、客户、设备操作或经营结果，就不得进入真实简历。不要提供“圆谎”话术。

## 二、证据状态

每个学生适配项目必须记录 `evidence_state`：

| 状态 | 含义 | 能否进入真实简历 |
|---|---|---:|
| `reference_only` | 纯教学案例，候选人没有执行 | 否 |
| `practice_ready` | 已有任务包，尚未执行 | 否 |
| `executed_unverified` | 候选人声称完成，但证据未检查 | 否；只做内部补强 |
| `evidence_verified` | 原始数据、过程文件、日志和交付物已核验 | 可以，写成自主/仿真/公开数据项目 |
| `real_experience_verified` | 真实实习、比赛、课程、实验室或校园活动已有事实证据 | 可以，按真实身份写 |

`resume_eligible=true` 只允许对应 `evidence_verified` 或 `real_experience_verified`。状态不能因为文案写得完整而升级。

## 三、参考案例与学生实践必须分轨

### 教学参考轨

- 可以完整构造候选人、公司、项目和数字，但必须单点披露为非真实案例；
- 文件、Manifest 和宣传页面标记 `reference_only`；
- 不提供去掉披露后即可粘贴的“真实候选人版”；
- 面试手册只讲案例逻辑，不教用户冒充经历。

### 学生实践轨

- 项目名称使用 `自主项目`、`公开数据分析`、`岗位实践` 或 `情景仿真`；
- 不虚构学校存在的比赛、课程、实验室、实习公司、客户或交易；
- 任务必须能由目标学生在说明的时间、预算、工具和权限下实际完成；
- 数据注明为公开采集、自采、教学样例或合成数据；合成结果只能写成仿真结果；
- 项目包不得预填候选人的最终决策、错误、结论或成果，必须留给学生执行；
- 未完成前只输出任务包、模板和验收标准，不输出可投递的个人简历 bullet。

## 四、一个可执行项目至少包含

1. **岗位目标**：练习哪一项真实岗位动作，不笼统写“提升能力”；
2. **资源边界**：时间、预算、设备、账号、软件和外部权限；
3. **输入来源**：公开页面、自采样本、教学数据或合成数据的取得方式；
4. **执行步骤**：学生实际需要采集、清洗、计算、设计、配置、测试或复盘什么；
5. **个人决策**：至少一个需要学生自己比较方案并说明理由的节点；
6. **偏差记录**：至少一次真实遇到的问题、错误、反馈或修改；不得预先替学生编好；
7. **证据产物**：原始数据、工作底稿、版本日志、截图/代码/模型和最终交付物；
8. **完成标准**：达到什么条件才从 `practice_ready` 升为 `executed_unverified`；
9. **简历边界**：完成后能写什么、仍然不能声称什么；
10. **追问门**：候选人能否现场打开文件并解释数据源、方法、选择、失误和限制。

默认提供2—14天的最小可行路径。需要付费账号、企业权限、资质、真实客户、生产设备或高风险操作时，必须给出不依赖这些资源的降级版本；无法降级时明确标为高资源依赖，不承诺项目可替代实习。

## 五、资源依赖等级

| 等级 | 典型岗位 | 学生项目能证明什么 | 不能替代什么 |
|---|---|---|---|
| 低 | 数据、内容、产品、运营、用户研究 | 公开数据处理、访谈、原型、内容发布、复盘 | 真实公司经营结果 |
| 中 | SaaS实施、供应链、财务、质量、合规 | 流程、主数据、测试、规则映射、情景决策 | 客户签字、系统上线、审计/注册结论 |
| 高 | 机械制造、半导体工艺、医疗检测、实验室和临床岗位 | CAD/CAE、公开或教学数据分析、实验设计、SOP/FMEA | 未接触设备的操作、产线调机、工艺放行、临床或检测结果 |

高资源依赖岗位必须在项目包中写出 `non_substitutable_gap`。没有真实设备或实验条件时，不把桌面分析包装成上机经验。

## 六、最低证据包

转换简历前至少核验：

- 一份保留来源和采集时间的原始输入；
- 一份有公式、代码、版本或修改痕迹的工作底稿；
- 一份按日期记录实际动作、问题和修改的执行日志；
- 一份学生本人完成的最终交付物；
- 一段限制说明，写明未使用的真实系统、客户、设备或业务数据。

只有最终报告、没有原始输入与过程文件，不足以进入 `evidence_verified`。

## 七、真实简历怎么写

允许的标题示例：

```text
酒店公开价盘与收益情景推演｜自主项目
电商品类与公开评论分析｜个人项目
进销存主数据与UAT实践｜岗位实践
薄膜测量教学数据分析｜仿真分析项目
医疗器械公开资料追溯分析｜自主研究
```

禁止写成：

- 某公司实习生、某客户项目或已上线项目；
- 学校不存在的比赛、课程、实验室或奖项；
- 未发生的GMV、入住率、良率、获证、交付和客户结果；
- 未操作过的设备、系统或平台权限。

简历只写学生实际执行的动作、实际产生的文件，以及明确标注的仿真结果。项目使用教学或合成数据时，在项目背景或首条 bullet 说明，不用小字隐藏。

## 八、面试表达

允许的表达结构：

```text
这不是企业实习，而是我独立完成的岗位实践。
数据来自____，我实际完成了____。
我在____处做过一次选择/修改，证据保存在____。
项目没有接入____，因此结论只代表____，不能当成真实业务结果。
```

不能提供冒充实习、编造协作者、伪造数据来源或规避背调的答案。候选人无法解释原始文件、关键公式、实际错误或限制时，回退到 `executed_unverified`。

## 九、交付前检查

- [ ] 教学参考与学生实践物理分离，参考简历标记 `reference_only`；
- [ ] 项目包状态为 `practice_ready`，没有预填学生最终成果；
- [ ] 项目不依赖虚构比赛、虚构公司或不可获得权限；
- [ ] 数据来源、资源依赖和不可替代缺口写清楚；
- [ ] `resume_eligible` 与证据状态一致；
- [ ] 未核验前没有生成可直接投递的个人项目 bullet；
- [ ] 核验后使用自主/公开数据/岗位实践/仿真标签，不冒充实习；
- [ ] 面试准备只教准确解释实际工作和限制，不提供圆谎方案。
