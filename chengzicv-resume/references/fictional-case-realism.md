# 教学案例简历真实感标准

## 何时读取

构造不存在的应届或初级候选人、生成教学示例简历，或审查案例简历是否像候选人材料而不是制作说明时读取。它只约束明确披露的 `reference_only` 教学案例，不允许把案例事实迁入真实候选人简历。需要给学生可执行项目或转换真实简历时，另读 `practice-to-resume-gate.md`。

## 一、披露一次，正文自然

案例简历必须在标题下方保留一个清楚且不可遗漏的披露块：

```text
教学示例｜非真实候选人；姓名、院校、公司、经历及数据均为案例设定；仅供结构参考，不可作为个人真实经历。
```

披露后使用正常模块名：`个人优势`、`教育背景`、`实习经历`、`项目经历`、`校园经历`、`专业技能`。

- 不在模块名、学校、公司或经历标题后反复添加“虚拟”“模拟”。
- 文件名用 `案例` 或 `示例` 表明材料属性，不要求重复写“虚拟案例”。
- 内部设计说明和面试教学手册仍可使用更完整的事实分层与风险说明。
- 用户要求删除唯一披露、把案例并入真实简历或冒充真实学籍/任职时停止。

## 二、候选人身份要形成生活时间线

应届或初级案例先建立候选人卡，再写公司项目：

```text
毕业届次与学历
学校所在城市、专业和目标城市
一条校园证据链
一条实习或岗位实践主线
三条有后文证据的个人优势
```

学校默认使用以下方式之一：

1. **地域匿名型**：如“深圳某财经大学”“北京某信息工程学院”，有地域和院校类型，不使用“某理工大学”这类无场景占位符；
2. **拟真校名型**：只有完成当前院校名单重名检查后才能使用，不得与真实院校混淆；
3. **真实候选人型**：只有用户真实事实支持时才使用真实学校名称。

不得给虚构人物安排真实学校学籍、真实竞赛奖项或可核验的真实联系方式。学校城市不必等于目标城市，但专业、学历、毕业时间和实习时间必须连贯。

## 三、个人优势固定为首个正文模块

案例简历在基本信息与披露块之后先写 `个人优势`，默认三条：

1. 岗位对象或领域经验；
2. 工具、方法或岗位交付能力；
3. 协作、问题处理或边界判断。

每条使用 `- **证据标签**：事实说明 + 结果/交付物`，并能在后面的实习、项目或校园经历中找到至少一条直接证据。不得使用可跨案例复制的“资料整理、问题跟进、沟通能力、学习能力”。

批量案例中，个人优势不能整句复用；换同义词但证据结构相同也算重复。

## 四、校园证据不是第二段实习

应届案例至少建立一条校园证据链，可从以下类型中选择最匹配的一到两种：

- 专业竞赛或校内挑战赛；
- 实验室、科研训练或课程设计；
- 学生会、班级、社团或党团工作；
- 社会实践、志愿服务或校园调研；
- 校园经营、媒体、活动或作品生产。

校园经历要处在学生世界中：服务对象通常是同学、教师、社团、实验室、校内商户或评审，不把公司经营问题缩小后再复制一遍。

每条展开经历至少说明：

```text
组织/活动与层级
时间、角色与团队规模
为什么做
本人承担的关键动作
使用的工具或方法
形成的材料、作品、演示或评审结果
```

### 强相关校园经历的可复述密度

与目标岗位强相关、需要单列的校园经历，不能停留在“整理数据—比较方案—完成答辩”的提纲层。默认写成 **1段背景 + 4—5条动作 + 1段成果**，并形成下面的可复述链条：

```text
规则与范围：赛制/课题要求、周期、对象、团队分工和本人负责项
工作底稿：原始数据从哪里来，包含哪些字段、样本或业务对象
处理方法：使用什么工具、公式、实验或判断口径，实际怎样操作
方案与决策：比较过哪些选项，依据什么阈值或约束作出选择
偏差与迭代：至少一次错误判断、异常、评审意见或方案修改
交付与结果：具体交付物、页数/表格/图表/演示，以及可解释的反馈
```

每条 bullet 只承担其中一个主要层次，不把多个阶段用顿号压成一条。面试官继续问“表里有哪些列、公式怎么算、为什么选A不选B、哪一轮做错、交了什么”时，正文应当已经提供可继续追问的入口。

竞赛、经营沙盘和课程实训还要额外交代：

- 一轮/一个阶段代表什么，参与者能控制哪些变量，哪些是题面或教师给定条件；
- 至少一个真实计算口径、字段组合、实验条件或方案对比，不只罗列工具名；
- 至少一次具体失误、约束或取舍，以及后续怎样修正；
- 成果优先写交付物规格和评审反馈，不用虚构名次填补细节。

“详细”不等于堆数字。每段仍只保留1—3个核心结果数字；团队规模、轮次、样本量、字段量和交付页数属于必要的工作痕迹，但每个数字都必须用于解释范围、方法、判断或结果。

优先量化工作痕迹，如参与人数、问卷数、活动次数、资料份数、SKU/样本量、内容篇数、测试用例或交付页数。结果可以是完成答辩、交付作品、解决一个具体问题或收到评审反馈，不必每案都虚构获奖。

渲染方式按证据价值决定：

- 与目标岗位强相关且细节充分：单列 `校园经历` 或 `项目经历`；
- 只有职位、奖学金或荣誉：压缩进教育背景；
- 与岗位弱相关且没有动作证据：删除，不为凑模块保留。

不得给虚构候选人套用真实全国赛事名称并编造名次、获奖或主办方背书。教学案例可使用自然的校级/院级活动名，但整个文档必须保留唯一披露。

## 五、外发简历禁止出现制作语言

以下内容只属于内部调研与设计说明，不进入简历：

- 岗位工作样本复刻；
- 公开岗位、官方规则或来源拆解；
- 示例数据、事实分层、案例构造过程；
- “未把公开资料写成个人经历”；
- 证据归档、生成说明、风险标签或模型口径提示。

简历只从候选人世界叙述：他在什么场景承担了什么任务，怎样完成，交付了什么，结果和边界是什么。

## 六、默认顺序

```text
基本信息与求职意向
教学示例披露
个人优势
教育背景
实习/工作经历
项目经历或校园经历（按证据强弱排序）
专业技能
证书与荣誉（可选）
```

技术、研究或竞赛是核心卖点时，可以把对应项目放在实习之前，但个人优势仍为第一个正文模块。

## 七、交付前检查

- [ ] 唯一披露清楚存在，模块名和经历标题没有重复“虚拟/模拟”；
- [ ] 学校采用允许的身份模式，时间线和专业方向连贯；
- [ ] 个人优势位于首个正文模块，三条均能回指后文证据；
- [ ] 至少有一条校园证据链，但是否单列模块由相关性决定；
- [ ] 校园经历处于真实学生场景，没有复制公司项目；
- [ ] 强相关校园经历具备规则范围、工作底稿、处理方法、方案决策、偏差迭代和具体交付，能够承受连续追问；
- [ ] 外发简历没有制作语言、内部口径和事实分层说明；
- [ ] 与同批其他案例相比，校园类型、个人优势和证据形式存在实质差异。
- [ ] 文件保持 `reference_only`，没有提供删掉披露即可迁入真实学生简历的版本；需要适配时已转学生实践轨。
