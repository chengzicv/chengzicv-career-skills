# 去 AI 味规则

去 AI 味不是把句子写口语，而是让句子有真实工作痕迹。

## 判断一句话有没有 AI 味

如果一句话符合下面任意情况，大概率有 AI 味：

- 抽象词很多，但没有具体动作。
- 动词很大，如赋能、促进、推动、打造、构建体系。
- 看起来适用于任何人，换个岗位也能用。
- 没有工具、对象、流程、结果。
- 用户面试时很难讲出细节。

## 替换原则

### 抽象词换成工具

不要写：

```text
具备数据分析能力。
```

改成：

```text
用 SQL 拉取用户行为数据，并用 Excel 透视表统计报名、到课和转化情况。
```

### 能力评价换成动作

不要写：

```text
具有良好的团队协作能力。
```

改成：

```text
和设计、前端、后端对齐需求边界，跟进接口联调和上线前走查问题。
```

### 业务大词换成流程

不要写：

```text
优化售后服务流程，提升服务效率。
```

改成：

```text
梳理从客户报修、客服登记到工程师上门的 10 个步骤，整理成 SOP 检查表，减少漏填和重复沟通。
```

### 结果导向换成结果证据

不要写：

```text
结果导向，推动业务增长。
```

改成：

```text
每周汇总渠道报名和转化数据，发现社群渠道到课率更高后，协助把活动预热重点转到社群。
```

## 禁用和慎用词

尽量不用：

```text
赋能、闭环、全链路、端到端、体系、抓手、沉淀、拉通、打通、协同推进、显著提升、全面优化、深度参与、深度赋能、关键作用、良好、优秀、扎实、丰富、敏锐、结果导向、数据驱动
```

不是绝对不能出现，但出现时必须问：

```text
这句话有没有具体动作和证据？
```

如果没有，就删。

## 更像真人的句子习惯

- 用“用、把、给、和、对、查、改、跑、看、整理、核对、联调、复盘”这类动作词。
- 少用“基于、围绕、通过、实现了、打造了”连续开头。
- 不要每条都写“针对 xxx 问题，通过 xxx，提升 xxx”，会显得模板化。
- 可以写得朴素一点，但要有信息。

例子：

```text
把客服高频问题整理成 FAQ 表，每周根据新增问题补充答案，方便新人快速查找。
```

这句话不华丽，但真实。

## 技术简历去 AI 味

技术简历不要写成论文摘要。

不要写：

```text
基于先进架构设计理念，构建高可用服务体系，显著提升系统稳定性。
```

改成：

```text
用 Spring Boot 拆分登录、用户信息和简历保存接口，接入 JWT 鉴权；上线前通过日志排查 token 过期导致的 401 问题。
```

不要写：

```text
引入缓存机制提升接口性能。
```

改成：

```text
把高频读取的用户配置放入 Redis，减少重复查库；接口平均响应从约 800ms 降到 300ms 左右。
```

如果没有数据：

```text
把高频读取的用户配置放入 Redis，减少重复查库，降低页面打开时的等待感。
```

## 最后通读检查

每段写完后问：

- 有没有具体工具？
- 有没有具体动作？
- 有没有具体对象？
- 有没有结果或交付物？
- 候选人面试能不能讲出过程？
- 这句话放到别人简历里是不是也成立？

如果一句话可以复制到任何人简历里，大概率要重写。
