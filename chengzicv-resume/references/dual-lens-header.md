# 头部资质、能力与代表成果

默认使用口语化直述体，按 `plainspoken-resume-style.md` 写头部。先交代姓名、岗位和材料已有的资质；「个人优势」块本身用片段式压缩写法（见下节），不用完整句——直述完整句用于经历正文，头部只追求信号密度，让 HR 与专业面试官 30 秒内抓到重点。

## 模块标题与位置

头部介绍块是独立模块，冠以 `## 个人优势` 标题，放在姓名与联系方式之下、专业技能之前。不允许没有标题的裸段落直接跟在联系行后面；联系行与个人优势块之间也不再放任何定位句——双重头部是冗余，定位职能由定位行独占。锚点（博客、作品集等真实链接）挂在联系行，材料未提供不虚构。

## 对标 JD 的压缩写法

- 全块 3-4 行、总 ≤ 200 字，用片段不用完整句：`·` 分隔信号片段，括号补限定词，流程压成箭头链（触发→清洗→发信）。
- 每行一个主题，同主题信号聚合成一行（获客工具链 = Clay + n8n + 数据，一行排完）；行顺序跟随 JD 任职要求的主题顺序，最稀缺、最可验证的主题放第一行。
- 转行桥接压进身份行做片段（"为转 X 方向专门跑通……"），不独立成句，不用"上述"回指。
- 加粗只给工具名、数字、极值词——扫读时眼睛只落在信号上。删光形容词和过渡词，高频残留一律删："实操过""会写""能用""跑通过""做……时""并用""日常工作用""相对""比较"。
- 用词对齐 JD 原文：JD 写"自动化流程"就不写"流程自动化改造"，JD 写"数据清洗"就不写"数据处理"（精确匹配优先，规则见 `dynamic-jd-ats-engine.md`）。
- 最稀缺、最可验证的信号放第一句（借鉴 GodSU resume-crafting 的"头部即胜负"：筛选方前 30 秒只读这里）。

坏 → 好对照（同一真实材料，2026-10-13 复测复盘）：

```text
坏（完整句，约 90 字）：实操过 Clay 的 waterfall enrichment（100+ 邮箱样本逐级补全主要字段并导出 CSV），并用 n8n 搭通 webhook 触发、数据清洗、邮件发送的自动化流程，实测发信。

好（片段一行，约 50 字）：**Clay** waterfall enrichment：100+ 邮箱样本逐级补全导出 CSV · **n8n** webhook 自动化流程：触发→清洗→发信，真实跑通
```

坏句三处违规：过渡词"实操过""并用"；完整句臃肿，同主题信号未用 `·` 聚合成行；"实测发信"未对齐 JD 原文"真实跑通"。

## 推荐理由式结构（有明确 JD 时的默认落地）

借鉴猎头推荐报告的行业共识（中文推荐评语三段式 + 英文 submission note 六块结构）：结论先行、证据对标 JD、主动暴露边界、状态动机收尾。个人优势块按"定位 + 匹配点 + 边界"落地：

1. **定位结论行**：一句话身份 + 推荐判断（"某在线教育公司在职工程师，跨境电商 ERP 销售出身；已跑通 Clay 富化与 n8n 发信实操"），整行加粗——相当于猎头报告里的一句话推荐（没有结论的推荐只是转发简历）。**有行业/业务垂类匹配时，垂类信号放第一行最显眼位置**（如"物业行业实施顾问""跨境电商 ERP 公司销售出身"）：工具几周能补齐、行业 know-how 不能，垂类匹配比技能匹配更稀缺。垂类信号从两侧找：JD 任职要求（"有 X 行业经验优先"）和公司业务描述（出海 SaaS 公司 ↔ 跨境电商从业经历）——后者 JD 里不明写，要主动推。**转行桥接靠证据不靠声明**：禁止写"为转 X 方向""希望转型"类动机声明（方向由求职意向行承担），把可迁移技能与新方向实操直接摆出，"凭什么转"让读者自己得出结论；且只写已完成的具体动作，claim 的规模不得超产出规模——两个独立练习不写成"跑通获客工具链"这类整合性业务级宣称。定位行只写名词性成分（身份、垂类），动作和数字全部放匹配点行——"已跑通 X 实操"这类小叙事句会稀释结论行。
2. **匹配点行（2-3 行）**：按目标岗位的能力维度分行，每行 = 能力标签 + 证据 + 数字，直接列与岗位匹配的点，不写过程词。学自真实 offer 跨行案例（土木转互联网产品）：标签直接用 JD / 岗位的能力词命名（"数据处理""B2B 获客漏斗"），不用自己业务的内部叫法。只写已完成、可验证的产出；还在学、没做出东西的技能不进头部。动词口径与材料一致：负责≠主导、参与≠独立、协助不升级为牵头。写完逐条核对 JD 任职要求：每条要求的关键词在块内至少出现一次；对不上的不硬凑，进边界与动机行。借势锚点紧跟弱实体（"某头部招聘平台旗下"类）。加粗给行首能力标签。
3. **边界与动机行**：主动写出最接近的 1-2 个真实缺口（未实操就写未实操，已列入补强计划）+ 当前状态与动机。猎头纪律：藏短板只会推迟到面试爆雷，主动暴露反而建立信任；只写真缺口，不自我美化。三条边界细则：缺口必须与目标场景相关（对目标场景不是缺口的不写——"无大厂经验"之于国企不是缺口）；海投无 JD 时本行删除（缺口无从对标），可保留动机行。

写作纪律（行业共识）：推荐语是论证、简历正文是证据——不复制正文细节；数据准确、不浮夸，每条证据经得起追问；顾问为推荐语言负责，简历场景下候选人就是自己的顾问。

## 头部类型选择（动笔前先判类型）

个人优势块的第一句押什么信号，按三个因素判断：有没有具体 JD × 候选人最强的资产是什么 × 目标公司用什么心态筛人。七种类型：

| 类型 | 第一句押什么 | 适用场景 | 风险 |
| --- | --- | --- | --- |
| 岗位信号优先型 | 逐条对 JD 任职要求 | 有明确 JD 的精准投递，**默认选项** | 最稳 |
| 稀缺身份优先型 | 创业经历、极值标签、开源身份 | 海投、初创公司、没有成熟画像的新岗位 | 大厂 HR 可能嫌不稳，有层级顾虑 |
| 背书优先型 | 名校、大厂、证书前置 | 国央企、传统行业、校招过筛 | 背书不硬时等于自曝其短 |
| 成果数字优先型 | 量化业绩（营收、增长、转化率） | 销售、运营、增长岗；社招有硬业绩 | 数字口径必须经得起追问 |
| 作品锚点优先型 | 头部直接给链接（GitHub、作品集、线上产品） | 开发、设计、内容岗 | 锚点质量差是反向证明 |
| 稳定可靠型 | 年限、在职状态、同城、可到岗时间 | 国央企、外包驻场、求稳上岸 | 天花板低 |
| 转行桥接型 | 第一句回答"你凭什么转"：可迁移技能 + 为新方向做的实操 | 转行者 | 不回答这个问题，HR 替你回答（否定） |

选择规则：

- 有明确 JD 时默认岗位信号优先型，顺序跟随 JD 任职要求。JD 匹配看两个维度：技能关键词匹配和行业/业务垂类匹配；两者都有时，垂类进第一行，技能关键词进证据行。
- 海投（无具体 JD）时退到人设型：在稀缺身份和成果数字中选候选人更硬的一个；海投用不了岗位信号型，因为没 JD 可对。
- 候选人正在转行时，无论选哪个类型，证据行都必须包含可迁移技能与新方向实操（回答"凭什么转"）；但不写"为转 X 方向"类动机声明——方向由求职意向行承担，证据自己说话。
- 类型可以叠加：主类型定第一句，其余类型只贡献单个信号（如岗位信号型 + 一个极值标签收尾）。
- 极值标签必须真实成立，不成立时加限定词收窄到成立（"深圳周榜 Top3"而不是"全国 Top3"）；所有信号需可验证或有锚点。

## 信息顺序

- 姓名、求职意向、资质、联系方式等按候选人材料填写。到岗时间和就业状态未明确时不猜。
- 用一两句说明做过哪些岗位相关工作，以及主要对象、方法或交付。
- 用完整句陈述代表成果：项目或平台是什么，候选人做了什么，得到什么有依据的结果。

不打印“HR透镜、Leader透镜”等内部设计标签。不把技术深度写成“精通、深入理解”堆叠，不用学历或高级词替代实际工作。

## 成果关系

以下只演示关系，不含可直接用于候选人的事实：

```text
在甲平台 [时间与榜单口径] 排名 [名次]，获得 [积分]；在乙平台发现 [漏洞类型]，定级为 [官方等级]。乙平台最高单洞奖励为 [金额]。
```

若材料未确认最高奖励属于该指定漏洞，金额单独交代平台口径。个人名次与团队名次、单次与累计奖金分清，原始官方等级和时间保持准确。多个成果可以自然连接，不孤立放一个“某平台漏洞：”标签。

有 GitHub、作品集或成果链接时使用候选人真实提供的地址；未提供时不虚构仓库。头部介绍与后文经历要能对应，避免重复所有项目细节。
