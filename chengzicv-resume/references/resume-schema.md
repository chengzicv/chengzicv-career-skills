# 简历数据模型

改写前先把所有材料解析进这个结构。之后的策略、改写、审计、岗位能力证据卡都只操作结构里的字段，不再回头翻原始材料。内容与呈现解耦：排版、模板、导出都不属于本 Skill。

## 为什么先结构化

- 多份材料合并时有统一落点，冲突显式化，不靠模型记忆。
- 局部重写时只动受影响字段，其他内容不漂移。
- bullet、事实、岗位能力证据卡靠引用串联，可辩护性可检查。
- 将来接工程化流程时，这个结构就是输出契约。

## 结构定义

```yaml
基本信息:
  姓名: ""
  电话: ""
  邮箱: ""
  城市: ""
  链接: ""            # 作品集/GitHub/个人主页，可选

身份定位:
  身份标签: ""         # 2027届·本科在读 / 应届生 / 2年经验 / X年经验，决定筛选池，缺毕业时间标[待确认]
  求职意向: []         # 最多 2 个相近方向，超过 3 个提醒拆多版简历
  求职状态: ""         # 可选：随时到岗 / 在职考虑新机会，不确定不写

个人优势:
  - 标签: ""           # 领域经验 / 问题解决 / 工具能力
    事实说明: ""
    结果: ""
    事实引用: []       # “事实1、事实2”等中文编号列表

教育背景:
  - 学校: ""
    学历专业: ""
    起止年月: ""       # 必须含毕业年月
    课程成绩奖项: ""   # 可选，应届才建议展开

工作或实习经历:
  - 公司: ""
    岗位: ""
    时间: ""
    项目背景: ""       # 1-2 句，≤50 字，不写愿景
    职责:
      - 小标题: ""     # 必填；通常 4-8 个汉字或相近视觉长度，按业务对象、功能模块、问题或结果命名
        正文: ""       # 场景+动作+工具+结果/交付物
        事实引用: []   # 中文事实编号
        能力证据卡引用: ""   # 使用“通用能力｜岗位专业能力｜经历名称”的可读标题，强 bullet 必填
    成果行: ""         # 真实结果或交付物，不编数据

项目经历:
  - 项目名: ""
    角色: ""
    时间: ""
    项目背景: ""
    技术栈: ""         # 只写原文出现或用户确认的
    职责: []           # 同工作经历职责结构
    成果行: ""

校园经历:                # 应届/在读候选人可用；学生会、社团、竞赛组织类经历落这里，不冒充实习
  - 组织或活动: ""
    角色: ""             # 如实写分工，如"部长（三人分工之一）"
    时间: ""
    职责: []             # 同工作经历职责结构，与目标岗位无关的整段压缩或删除

专业技能:
  - 能力域: ""
    工具: ""
    能完成什么: ""

其他:
  证书竞赛: []         # 可选，只留和目标岗位相关的
```

## 填写规则

- 缺失信息一律标 `[待确认]`，不留空、不猜、不用模板示例值顶替。
- 数字必须能溯源到中文事实编号，溯源不了的进入“待验证主张”（见 `fact-ledger.md`）。
- 强 bullet（有数字、有强动词、有独特卖点）的 `能力证据卡引用` 必填；填不上说明能力证据还没挖完整，回追问阶段。
- 渲染工作、实习、项目和校园经历时，职责固定输出为 `- **小标题**：正文`；整段压缩为一行概述时不创建职责 bullet。
- 解析已有简历时保留原文措辞进台账 `rawText`，改写只发生在结构字段里，保证 diff 有据可查。
- 板块整体为空就整块删除，不输出空标题。

## 与交付格式的关系

本结构是内部工作格式。对用户交付时按 `diff-output.md` 的完整简历格式渲染成 Markdown 文本；用户要求工程化对接时可直接输出本结构的 JSON 形式。
