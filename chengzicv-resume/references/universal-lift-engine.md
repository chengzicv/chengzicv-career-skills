# 跨岗位取材与经历补强

按岗位选择具体对象、动作、方法和成果，直述写法以 `plainspoken-resume-style.md` 为准。补强来自已有材料中的工作细节；不能把日常工作自动改成架构、模型或飞轮，也不要求每条都有量化收益。

| 岗位 | 优先寻找的具体对象与动作 | 材料中可用的成果 |
| --- | --- | --- |
| 技术、研发、安全、运维 | 接口、组件、协议、请求、数据；开发、分析、验证、失败处理、复测。 | 交付代码或报告、测试环境与结果、覆盖范围、实际性能指标。 |
| 产品、设计 | 用户场景、功能、图纸、原型；调研、方案取舍、评审、出图、验证。 | 评审记录、版本交付、试用反馈、已验证的业务变化。 |
| 运营、市场 | 内容、渠道、投放、社群、商品；选题、发布、用户承接、对比记录。 | 发布量、咨询量、活动执行、真实转化或留存数据。 |
| 销售、商务 | 客户类型、产品、报价、账期；开发、演示、谈判、签约、跟进。 | 合同、回款、签约周期和有口径的个人／团队业绩。 |
| 财务、人事、法务、行政 | 发票、报表、制度、合同、招聘；核对、审核、协调、整理、记录。 | 台账、审核结果、到岗记录、已测量的周期或差错。 |

保留真实领域词：技术岗位可以写框架、协议和算法；运营岗位可以写渠道、内容与转化；设计岗位可以写软件、图纸与评审。跨部门沟通不自动写成 API 对接，Excel 整理不自动写成数据解耦，普通选题不自动命名为双轨模型。

材料只有“速度变快”“效果很好”时，寻找已有对比记录、交付物或验证过程。没有证据就写实际动作和已知交付，不按行业水平推算为已发生的数字。冲高候选补全按 `evidence-safeguard.md` 独立记录。

材料少时可按时间、对象、个人动作、方法、结果查找现有细节，不套固定问卷。用户要求先写时，使用已有材料完成，不通过连续追问拖住交付。
