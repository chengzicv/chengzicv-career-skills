# JD 对照与 ATS 优化

目标是让招聘方（机器和 HR）都看懂已有经历怎样回应岗位要求。文风以 `plainspoken-resume-style.md` 为准，事实边界以 `evidence-safeguard.md` 为准：不把 JD 要求当成候选人已经具备的能力。用户提供 JD 时本文件为必读，交付前必须输出文末的 ATS 核对报告。

## 一、机筛机制认知（2026 年调研校准，数据均为转引）

ATS 的工作只有三步：解析文件提取纯文本 → 提取关键词与 JD 比对 → 打分排序。基于这个机制定策略：

- **排序而非拒绝**：92% 的招聘方确认他们的 ATS 不会因为简历内容自动拒绝（Enhancv/HR.com 2025 对 25 名招聘方的调研）；真实风险是排在 150 名而招聘方只翻前 20。目标是排进前 10-15%，不是"骗过一个拒绝阈值"。国内资料常讲 60-75% 匹配率阈值（Jobscan 口径），两说并存，按"尽量提高有效命中"执行即可。
- **两派系统并存**：老系统和多数国内平台做精确字符串匹配，不认同义词（JD 写"数据分析"，你写"数据处理"就可能判不匹配）；Workday、Greenhouse、Lever 及 LinkedIn Hiring Assistant（2025 Q4 上线）等已上语义匹配。策略：精确原词优先，同义映射兜底，两者不冲突。
- **位置有权重**：技能区被重点扫描；简历前 1/3（头部介绍、技能区、最近一段经历）权重最高；页眉页脚可能完全漏解析。核心词往前放，进技能区，进具体动作。
- **解析失败是独立死因**：表格、图片、分栏、文本框会导致解析乱码（国内资料称约 35% 淘汰与能力无关、纯属格式问题，口径存疑但方向可信）。用标准小节标题（工作经历/项目经历/专业技能/教育背景），导出格式按平台要求，没要求时优先 .docx。
- **堆砌有惩罚**：机械重复同一个词会被降权，人也读不下去。一个词出现一次、放对位置，胜过重复五次。

## 二、关键词逆向拆解（拿到 JD 先做这步）

把 JD 里的词分三类、标三级，输出一张词表再动笔：

1. **硬技能/工具词**：编程语言、软件、平台、证书（Python、Clay、PMP）。特点是"有或无"，无法翻译。
2. **方法论/行业词**：概念和方法（ICP、lead scoring、转化漏斗、用户增长）。特点是跨行业有同义族，可以映射。
3. **软技能词**：协作、沟通、Owner 意识。机筛权重低，进具体动作即可，不单独堆。

分级：**核心词**（JD 反复出现或在任职要求里，必须原词命中或明确映射）→ **相关词**（出现一次，能挂就挂）→ **衍生词**（上下文自然带出即可）。

同时标出硬性门槛（学历、年限、证书）——这是过滤条件不是关键词，不满足时在补强清单里说明，不在简历里伪装。

## 三、四层优化（顺序不可乱）

### 第 1 层：诚实映射（白捡的分）

候选人真实做过的事，用 JD 的术语重新命名。典型手法是**括注映射**：原表述 + JD 术语括注，如"目标人选画像（ICP）建模"、"触达到入职的转化漏斗（MQL→SQL 式分级跟进）"。

边界：

- 只能映射**已确认事实的同义术语**。猎头的"按岗位要求圈定人选画像"映射成 ICP 是翻译；没做过 lead scoring 写 lead scoring 是发明。
- **实现类细节必须用户确认**。概念上接近不等于事实成立："上传即生图"到底是 webhook 回调、消息队列还是定时任务，问完再写。
- 工具词不可映射。没用过 Clay 就是没用过，不存在"约等于用过"。

### 第 2 层：结构与位置

- 技能区按 JD 任职要求的顺序重排，JD 先问的在前。
- 核心词至少出现两处：技能区一次（机筛锚点），最近经历的具体动作里一次（人和语义匹配都看上下文）。
- 「个人优势」块的背景层与能力层覆盖最重要的 2-3 个岗位任务，用词对齐 JD 原文。
- 用标准小节标题，不用表格、分栏、图标、文本框。

### 第 3 层：真实补强

前两层做完仍缺的核心词，转成补强清单交给用户：每条写清"做什么动作、多久、做完简历里能写什么"。例："注册 Clay 免费版跑通一次 waterfall enrichment（2-3 天）→ 技能区可写'实操 Clay 完成多数据源线索富化'"。补强完成后更新简历，词随真实经历增长。这是初版到第 2 版的循环，不是一次交付。

### 第 4 层：底线

上面三层做完还差词，就让它差着。不编造经历、技能、工具、数字。49% 的招聘经理能识别明显 AI 生成且缺乏个性的简历（Resume.io 2025，转引）；虚构内容在技术面和背调中都会暴露。机筛不过是慢死，穿帮是立死。

## 四、对照写法细则

- 工具与技术：写清实际使用工具做了什么，保留准确名称。
- 协调、合规、写作等能力：用真实协作对象、审核动作、文档和结果说明，避免仅写"能力强"。
- 行业方法和标准：只有实际学习、采用或验证的材料才写进相应层级，不能将了解写成精通。
- 指标：使用原始口径，不因为 JD 提到增长或性能就增加数字；归因不含糊的数字加限定（"得益于团队配合"）。
- 没有 JD 时先按已知求职方向完成通用版，避免猜测某家公司的当前要求。

## 五、交付前 ATS 核对报告（强制交付物）

每版有 JD 的简历交付时，随附一张核对报告：

```text
核心词命中：  [原词出现的，标注出现位置]
映射命中：    [括注映射的，注明映射依据的真实经历]
缺口：        [每个缺口给一条补强动作：做什么 / 多久 / 做完能写什么]
结构检查：    技能区顺序 / 前1/3 覆盖 / 标准标题 / 无表格分栏
事实边界：    本版无任何未经用户确认的工具、技能、数字（或列出待确认项）
```

## 六、评审标准（给评审者用）

评审一版"简历 × JD"按此表打分，事实边界为一票否决：

| 维度 | 通过标准 |
| --- | --- |
| 事实边界 | 所有工具、技能、数字可回溯到用户确认过的材料；任一编造即整体不通过 |
| 核心词覆盖 | 核心词 100% 有处置：原词命中、合法映射、或进补强清单；不允许"漏掉不处理" |
| 映射正确性 | 每条映射能说出对应的真实经历；实现类细节有用户确认记录 |
| 结构 | 技能区按 JD 顺序；核心词进前 1/3；标准小节标题；无表格/分栏/图片 |
| 自然度 | 无关键词堆砌；每句话删掉术语后仍是有信息的事实陈述 |
| 补强清单 | 每个缺口可执行（做什么、多久、做完能写什么），不是"建议学习 XX"式空话 |

## 七、回归测试方法（埋词测试）

测试 ATS 优化能力用合成案例，不用真实投递验证：

1. **造虚拟 JD**：目标岗位 + 埋三层词——工具词（选候选人肯定没用过的，测诚实性）、方法论词（选有同义经历的，测映射能力）、技能词（候选人已有的，测白捡命中）。
2. **埋词清单单独存档**，不进测试提示词。清单写清每个词属于哪层、期望的处置方式（命中/映射/补强）。
3. **模拟小白调用**：只给简历路径 + JD 路径 + 一句糙需求，不提示任何方法。
4. **核对四项**：词表三层各自的处置是否符合预期；未用词是否零编造（测底线）；是否输出 ATS 核对报告；补强清单是否可执行。
5. **通过标准**：事实边界零违反 + 可映射词全部完成映射 + 缺口全部进补强清单。工具词命中率不是通过标准——候选人没用过的东西，命中了反而是事故。

测试案例库由测试主持人在套件之外单独保管，本文件不记录任何具体案例路径。执行简历任务时不得检索、读取埋词清单；发现当前任务的材料与某个测试案例重合时，按正常任务处理并照常执行事实边界，不针对测试调优。
