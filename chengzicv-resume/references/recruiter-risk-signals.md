# 企业敢招证据链

本文件用于学生、应届、初级、转岗、学历不占优、项目同质化，或投递中小企业/传统行业/执行型岗位的简历优化。

核心目标：不要只把候选人写得“更强”，还要写得“更好判断、更低风险、更像这家公司敢招的人”。

## 触发场景

出现以下情况时读取本文件：

- 用户说项目同质化、学历不足、学生简历太像、想从一堆学生里脱颖而出。
- 候选人是应届生、实习生、初级岗、转岗候选人。
- 目标岗位在中小企业、传统行业、业务执行型团队。
- 简历里有大量高并发、微服务、分布式、战略、体系等高层级表达，但事实主要是课程项目、比赛项目、练习项目或实习执行。
- 用户强调稳定性、意愿度、可塑性、作品集、Demo、交付物、Boss 打招呼。

## 核心判断

学生简历差异化不是把项目写得更高级，而是把候选人写得更好判断。

```text
岗位差异化 = 场景选择 + 交付物证据 + 风险降低 + 可迁移表达
```

解释：

- **场景选择**：项目或经历是否像企业真实需求，而不是只像课程作业。
- **交付物证据**：招聘方能不能通过链接、截图、文档、图纸、台账、Demo 快速验证。
- **风险降低**：简历是否主动降低“只会练习、不稳定、太大厂、不会交付”的顾虑。
- **可迁移表达**：把工具能力翻译成目标岗位能用的工作成果。

## 岗位示例不是覆盖范围

本文件里的 Java、机械结构、运营、销售只是示例，不是可处理岗位范围。遇到没有列出的岗位时，不能硬套已有示例，也不能因为没有示例就降级处理。

所有岗位都先按下面的通用算法抽象：

```text
这个岗位招来做什么
→ 入职前 1-3 个月最可能接什么任务
→ 招聘方最怕候选人哪里不靠谱
→ 候选人有什么材料能证明自己接得住
→ 这些材料中哪些能被点开、查看、复用或追问
→ 简历顶部、项目命名、经历 bullet 怎么围绕这些证据重组
```

如果是未覆盖岗位，优先输出岗位自己的证据链，而不是复用 Java/机械/运营/销售的词。

示例：

- 设计岗：看作品集、改稿过程、设计规范、落地页面、用户反馈，而不是只写“审美好”。
- 人事岗：看招聘漏斗、候选人台账、面试安排、入离职流程、社保材料核对，而不是只写“沟通能力强”。
- 采购岗：看供应商对比、询报价记录、合同/付款节点、物料台账、异常处理，而不是只写“谈判能力强”。
- 客服岗：看 FAQ、工单记录、问题分类、升级流程、满意度/响应时长记录，而不是只写“服务意识好”。
- 教务岗：看排课表、学员跟进表、续费提醒、家长沟通记录、异常处理 SOP，而不是只写“耐心负责”。

## 先做岗位风险画像

优化前先判断招聘方可能担心什么。不要只拆关键词。

```text
目标岗位：
企业真实需要：
招聘方可能担心：
候选人现有证据：
还缺的证据：
简历打法：
```

常见顾虑：

- 学历或学校不占优。
- 项目和其他学生高度同质化。
- 技术词很满，但看不出能不能做业务系统。
- 项目很炫，但和中小企业真实需求不匹配。
- 候选人看起来太大厂导向，来了可能不稳定。
- 会工具，但没有可交付材料。
- 会做项目，但没有测试、部署、文档、图纸、台账、复盘。
- 求职方向太散，意向度不清楚。

## 证据优先级

强信号通常不是“我熟悉 XXX”，而是能被检查的交付物。

可验证交付物包括：

- 技术岗：线上 Demo、测试账号、源码仓库、README、接口文档、数据库说明、部署说明、测试记录、压测记录、迭代记录。
- 机械结构：作品集、总装图、爆炸图、关键零件工程图、BOM、3D 打印/装配调试照片、设计修改前后对比。
- 运营：选题表、排期表、发布记录、活动复盘表、用户反馈分类表、SOP、数据看板截图、FAQ。
- 销售：客户线索表、跟进记录、客户分层规则、异议话术库、报价/合同流程说明、拜访纪要、周报、转化漏斗。
- 职能/财务/行政：台账、核对清单、SOP、模板、报表、异常清单、交接文档。

写简历时要优先使用已经存在的交付物。没有证据时不能写成事实，只能放到“建议补充”或“追问清单”。

## 表达原则

不要只写能力标签：

```text
熟悉 Java 后端开发，掌握 Spring Boot、MySQL、Redis。
```

改成岗位可用表达：

```text
做过工单/CRM 类业务后台，能完成需求拆解、表结构设计、接口开发、权限鉴权、接口测试和部署说明整理。
```

不要只写工具：

```text
熟练使用 SolidWorks。
```

改成工程交付表达：

```text
可使用 SolidWorks 完成零件建模、装配体搭建、爆炸图和基础工程图输出，并配合整理 BOM 和装配说明。
```

不要只写性格评价：

```text
沟通能力强，抗压能力强。
```

改成过程证据：

```text
维护客户跟进台账，记录客户来源、需求、预算、跟进状态和下一步动作，并整理常见异议回复话术。
```

## Java 初级/实习写法

目标不是写得像大厂候选人，而是让中小企业看到能做业务系统、能测试、能部署、能交付。

优先项目场景：

- 小型企业工单派单管理系统
- 客户线索 CRM 与跟进记录系统
- 门店进销存与库存预警系统
- 售后报修与处理进度管理后台
- 内容审核/素材管理后台
- 企业知识库与工单摘要系统

顶部定位示例：

```text
Java 后端/全栈型实习生｜能把业务流程做成可上线的管理后台
做过工单/CRM 类业务系统，覆盖需求梳理、表结构设计、接口开发、权限鉴权、接口测试、基础压测和 Sealos/Docker 部署；可提供线上 Demo、测试账号、接口文档和部署说明。
```

项目第一句话示例：

```text
项目模拟小企业售后报修场景，把客户报修、工单分配、处理进度和结果记录做成一个可登录使用的后台系统。
```

可写技术点：

- 登录鉴权：JWT / Spring Security、角色权限、token 过期、未授权访问。
- 接口测试：Postman / Apifox，覆盖正常提交、缺参、无权限、重复提交。
- 基础压测：JMeter，记录平均响应、错误率、异常日志。没有真实数据不要写 QPS。
- 基础安全：BCrypt 加密、参数校验、敏感信息不进日志。
- 部署交付：Sealos / Docker / Nginx / 环境变量 / 测试账号 / 部署说明。

谨慎表达：

- 不要把课程项目写成高并发系统。
- 没有生产经验，不写高可用、微服务治理、海量数据、企业级架构。
- 压测可写“基础压测”，不要写“支持高并发”。

## 机械结构助理写法

目标不是只证明会软件，而是证明能把设备想法整理成可建模、可出图、可装配的结构资料。

顶部定位示例：

```text
结构助理工程师｜能把设备方案整理成三维模型、装配关系、物料清单和说明文档
参与整机建模、样机装配和 3D 打印件验证；可提供 SolidWorks 建模作品集、装配图、零件图或项目说明。
```

项目第一句话示例：

```text
项目面向山药挖收场景，围绕移动作业、挖收机构、输送结构和装配调试，完成设备结构建模、零件拆分和样机验证资料整理。
```

可验证证据：

- 整机总装图
- 爆炸图
- 关键零部件工程图
- BOM 或零件清单
- 3D 打印/装配调试照片
- 设计修改前后对比
- “结构问题 - 修改动作 - 验证结果”的说明

风险提醒：

- 如果作品集只有模型截图，不要把“工程图、BOM、加工说明”写得太满。
- 如果候选人主要负责建模，不要写“主导整机设计”；可以写“参与”“完成”“协助调试”。

## 运营助理写法

目标不是写“有网感”，而是证明能把运营动作做成可复盘、可交接、可持续的流程。

顶部定位示例：

```text
运营助理｜能把内容/活动从选题、发布、数据复盘做到可交接
做过内容排期、用户反馈整理和活动数据统计，能用 Excel 维护台账、复盘报名/到课/转化数据，并整理 SOP 降低重复沟通成本。
```

可验证证据：

- 内容选题表
- 发布排期表
- 活动复盘表
- 用户反馈分类表
- SOP 文档
- 数据看板截图
- 私信/客服问题 FAQ
- 活动前后数据对比

## 销售助理 / BD 写法

目标不是写“外向”“抗压”，而是证明能把客户跟进做成可管理流程。

顶部定位示例：

```text
销售助理/BD｜能按线索分层、跟进记录和话术复盘推进客户转化
能维护客户台账，记录客户来源、需求、预算、跟进状态和下一步动作；可根据常见异议整理回复话术，配合报价、合同和回款节点推进。
```

可验证证据：

- 客户线索表
- 跟进记录模板
- 客户分层规则
- 常见异议话术库
- 报价单/合同流程说明
- 拜访或电话沟通纪要
- 周报模板
- 转化漏斗记录

## 输出要求

如果本文件被触发，输出里至少体现一项：

- 简历策略中说明“企业可能担心什么”和“这版怎么降低顾虑”。
- 在简历中加入作品集、Demo、文档、图纸、台账等可验证证据。
- 对证据不足的地方做风险提醒。
- 给出 3-7 条可执行的补强任务，例如“补 1 张爆炸图”“补接口文档链接”“补客户跟进台账截图”。

不要输出心理学论文给候选人或 HR。论文和理论只用于内部判断，不写进简历成品。
