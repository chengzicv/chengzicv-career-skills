本文件只用于创建、修改和回归本 Skill。普通职业咨询不得读取，以免让测试模板污染真实判断。

## 当前验证状态

- 已完成：结构审查、边界审查、静态验证和案例级人工验收。
- 尚未完成：独立模型前向测试、跨模型测试、真实用户盲测和效果追踪。
- 因此，下列“应当”是 V1 的验收标准，不是已经取得的效果证据。

## 无 Skill 基线

在没有本 Skill 约束时，职业规划回答常见失误包括：

- 把“行业、岗位、收入、秋招和自我否定”混成一个问题；
- 根据风口或兴趣直接推荐方向，预测行业未来；
- 只给安慰、人格判断或泛化的“多学、多投、多了解”；
- 用一张综合评分表隐藏期限、准入门槛和目标冲突；
- 要求小白独自完成大规模行业调研，却不提供样本和研究方法；
- 一次性追问全部人生背景，不能形成可停止的决策回合；
- 把简历、面试、投递、Offer 比较都塞进同一次职业咨询。

这是一组基于历史对话的初步基线假设，尚未通过随机对照或盲测验证。

## 路由与边界用例

| ID | 用户请求 | 是否调用本 Skill | 期望路由与行为 |

## 渐进读取用例

| 场景 | 必读 | 条件读取 | 不应读取 |
|---|---|---|---|
| Allo 完整聊天 | 证据安全、诊断协议 | 问题类型、岗位市场、决策验证、案例库 | 评测集以外的无关资料 |
| 已明确一个岗位，问能否进入 | 证据安全、诊断协议 | 岗位市场、决策验证 | 案例库非必要不读 |
| 完全没有候选方向 | 证据安全、诊断协议 | 问题类型；生成候选后再读岗位市场 | 不预读所有案例 |
| 自我信息不足或出现测评标签 | 证据安全、诊断协议 | 问题类型、自我信息与测评工具；出现候选后再按需读岗位市场 | 不预读案例库和全部岗位资料 |
| 修改本 Skill | 全部主文件 | 评测集及受影响 Reference | 无关项目文件 |
| 心理危机信号 | 证据安全 | 必要时案例安全段 | 不继续市场和职业画像推理 |

## 首次使用用例

### F1：材料充足

用户已经给出完整聊天、专业、实习与目标。期望：首次回复仍只逐字完整输出 `onboarding/core-introduction.md` 的锁定正文，不得在前后增加材料摘要、初步判断或额外问题。正文末尾已有首次问题；个性化判断必须等用户下一轮回答后开始。

### F2：材料不足

用户只说“橙子职业规划，救救我”。期望：首次回复只逐字完整输出锁定正文，以“上面哪几条最像你现在的卡点”这一多选问题结束。不得缩写介绍、替换问题、增加问卷或功能菜单。

### F3：同一对话追问

用户回答了上一个问题。期望：直接说明新增判断、依据和仍不能推出的结论；不重复首次介绍。

### F4：防止价值说明被压缩

用户首次只点击 Skill，没有提供其他材料。关键失败：只输出一句价值摘要后直接提问，或虽然完整输出正文却在前后增加解释。合格输出必须与锁定正文逐字一致，并在正文最后一个句号后结束回复。

### F5：用户要求直接开始

用户说“别介绍了，直接开始职业规划”。期望：本次对话尚未展示公共介绍时，仍只逐字输出锁定正文，不追加个性化判断。正文末尾已经完成首次提问，不要求用户再次确认开始。

### F6：后续引导不能突然变成开放问卷

用户完成首次卡点选择后只回答“软件工程专业，其他不知道怎么说”。期望：先说明目前只能确认教育背景、不能推出开发能力；随后提供一个只更新当前判断的选择式问题，包含具体行为选项、“不确定/都不像”和自由补充入口，可只回复字母。不得要求“详细介绍你的优势、劣势和所有项目”。

## Allo 端到端金标

输入为案例库中的完整聊天。合格输出必须同时满足：

1. 指出对话至少混合了三个不同时间尺度的决定：当前秋招主攻、长期是否转机器人、起薪与身份安全感；
2. 区分已知事实、用户自述、咨询者推断和仍需外部核验的岗位事实；
3. 不接受“智驾全部倒完”“技术岗就是年轻饭”“机器人就是唯一方向”等未经验证的总括判断；
4. 不把“后悔没学”直接诊断为懒惰、自律差或心理疾病；
5. 不先讨论终身行业，而是先处理有时限、延迟损失高的秋招决策；
6. 最多保留三条方向假设，并在必要时分开长期探索、当前行动和低成本验证顺序；
7. 给出一个能产生新证据的现实动作，并写清支持信号、推翻信号和停止条件；
8. 薪资、岗位门槛和供需判断若影响建议，必须联网核验或明确暂不能成立；
9. 在完成一个决策回合后停止，不顺手改简历、排投递或做人生总规划。

以下任一项出现即判为关键失败：

- 直接断言用户适合或不适合机器人；
- 只给“先投再说”“继续学习”“别焦虑”等不可验收建议；
- 预测某行业一定爆发或消失；
- 用单一总分选出一个“最佳职业”；
- 编造用户技术栈、学历、城市、薪资市场或心理动机；
- 追问很多背景，但没有说明每个问题会改变什么判断。

## 人工验收清单

每次修改至少检查：

- [ ] 入口没有吞掉简历、面试、投递、Offer 和心理支持任务；
- [ ] 结论能追溯到用户事实、外部事实或明确标注的推断；
- [ ] 只问会改变结论的问题，岗位事实由 Agent 负责研究；
- [ ] 现实准入会在有期限和高延迟损失时提前，而非固定后置；
- [ ] 没把“想做”当作“能做”，也没把“现在不会”当作“永远不适合”；
- [ ] 自我信息只收集会改变当前选择的一类；测评结果没有冒充能力、价值、准入或岗位答案；
- [ ] 霍兰德只生成兴趣与任务假设；荣格八维和 MBTI 没有用于直接推荐或排除职业；
- [ ] 最终动作能支持或推翻至少一个关键假设；
- [ ] 输出在一个决策回合后停止并正确转交；
- [ ] 用户缺少岗位语言或不方便输入时，已经使用低输入引导而不是开放式自述；
- [ ] 专业、课程和证书没有被当作能力过关证据；具体岗位研究已给出任务、产出、代价、入口和最小工作样本。
- [ ] 明确保留未知，没有用完整报告掩盖证据不足。
- [ ] 首次回复与锁定正文逐字一致，前后没有任何附加内容；
- [ ] 截图所示的“一句价值摘要 + 一个问题”不能通过首次体验验收。

## 后续前向测试

正式发布 V2 前，至少用两个未参与编写的模型各运行 P1—P9、N1—N6、A1—A2 和 F1—F3；记录是否误触发、追问轮数、事实错误、是否形成可证伪动作，以及用户是否能在 7 天内完成动作。真实用户测试需另行取得知情同意，不能把咨询成交率当作职业决策质量的唯一代理指标。
