# ChengziCV Candidate Profile Evals

## 准入与中心任务

- 无 Skill 基线容易把“没有简历”处理成长表单，或直接生成一份事实不足的简历；本 Skill 应先形成可暂停、可继续、可交接的求职档案。
- 中心产物是候选人档案、材料索引、待确认项和阶段快照，不是岗位版简历、职业结论或面试评分。

## 应触发

1. “我是大三学生，什么材料都没有，先帮我从零建个求职档案。”
2. “我还没写简历，但有课程 PPT、大作业和几张竞赛奖状，可以先帮我整理吗？”
3. “继续补我的求职档案：六级是 2025 年 12 月过的。”
4. “先暂停，把目前知道的背景、材料和还缺什么总结给我。”
5. “给我一份可以快速填空的大学生简历底稿，我想到哪里填到哪里。”

## 不应触发与相邻混淆

1. “这是简历和 JD，直接改成一版能投的。”应进入 `chengzicv-resume`，不重新建档。
2. “我不知道该考公、做运营还是转产品。”应进入 `chengzicv-career`，建档不得替代方向判断。
3. “后天 HR 面，按这份简历模拟一下。”应进入 `chengzicv-interview-mock`。
4. “这是刚结束面试的录音，帮我复盘。”应进入 `chengzicv-interview-review`。
5. 用户只要下载一个通用 Word 模板时，不得强迫进入多轮建档；交付基础模板即可。

## 首次体验

1. 材料齐全：介绍后立即接收、编号和提取材料，输出第一版档案快照，不要求用户重新概述。
2. 完全零材料：介绍后只索取一组最小背景，例如当前学历/专业/毕业时间与最着急的求职问题；不得一次抛出完整简历表单。
3. 用户只说“我什么都没有”：用大作业、PPT、竞赛、社团、兼职和证书等例子帮助识别素材，但一次只推进一个板块。
4. 后续回复不得重复首次介绍；应先回显新增或修正了什么，再继续一个问题。
5. 用户只说“软件工程专业”时，只确认专业字段；不得自动写入 Java、开发、测试或“专业基础扎实”。下一问应通过经历选项、材料或最小任务寻找能力证据。
6. 用户说“不知道还能描述什么”或不方便打字时，给一张只推进当前板块的低输入卡；包含具体选项、不确定/跳过/自由补充入口，并允许只回复字母。

## 档案与记忆边界

1. 只记录用户明确提供或材料能够直接支持的事实；模板示例、JD 和案例不得写入用户档案。
2. 普通聊天不得承诺跨会话记忆。暂停时必须交付可复制的档案快照；下次只能依赖当前可见历史或用户带回的快照。
3. 写入本地或外部系统前必须获得用户明确授权和目标位置；不得把真实候选人资料写进 Skill 源目录、Evals 或公开仓库。
4. 姓名、电话、邮箱可延后到生成外发简历时补充；性别、年龄、照片、婚育等为可选敏感信息，不默认追问，不参与能力或岗位判断。
5. 专业、课程、证书和项目标题只能作为接触背景；技能条目必须记录熟练边界、支持任务或作品和来源。

## 端到端交付 Rubric

- 产出已确认信息、材料索引、待确认项、当前求职状态和下一步建议。
- 每段经历至少保留名称、时间、角色、动作、结果/交付物和来源；缺失项明确标待确认，不补造。
- 用户说“暂停”“退出”“总结现状”时立即停止提问，输出当前快照和一句可用于继续的承接语。
- 方向不清时只把已确认档案交给 `chengzicv-career`；方向明确并需要成稿时交给 `chengzicv-resume`。
- 跨模型尚未验证，不声称在所有宿主中都能自动保存或恢复。

## 渐进读取

- 任何建档任务读取 `references/intake-protocol.md`。
- 建立、更新或汇总档案时读取 `references/profile-schema.md`。
- 用户需要可复制底稿时使用 `assets/candidate-profile-template.md`；需要简历形态的快速填空稿时使用 `assets/zero-material-resume-template.md`。
