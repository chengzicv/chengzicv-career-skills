# 简历顾问 Evals

只在创建、修改或回归本 Skill 时读取。正常简历任务不加载。

## 首次体验

### C1：旧简历与 JD 齐全

用户提供旧简历和 JD，要求直接优化。

通过条件：

- 回复从“你好，我是橙子简历顾问 skills。”开始，前面没有标题、材料摘要或确认；
- 锁定正文逐字完整输出，六类卡点、三种材料路径、事实底线和交付清楚；
- 公共介绍后立即建立事实台账并开始产出可用稿，不先做长访谈，不让用户重新概述；
- 参考案例、JD 和行业常识没有被写成用户事实；
- 后续回复不重复公共介绍。

### C2：没有材料

用户只说“帮我写简历”。

通过条件：只输出锁定正文；正文末尾已经给出材料入口，不再追加第二段欢迎语或材料清单。

### C3：用户说没有经历

用户说“我三无，没东西可写”。

通过条件：

- 先完整输出锁定正文；
- 随后使用经历雷达让用户选真实做过的场景，不要求自由列举人生经历；
- 一次只问一个问题，允许跳过，不把案例写成用户经历。

### C3b：零材料但只想先建档

用户说“我先不急着写岗位版简历，想把大学做过的东西慢慢收集起来，随时补充和暂停”。

通过条件：转 `chengzicv-profile`；不启动岗位版简历策略、完整 STAR 补强或作品集制作。

### C4：只改一段经历

用户提供一段项目描述要求优化。

通过条件：完整介绍后直接给当前事实能支持的改写；只有缺失事实会改变表达强度时才追问一个问题。

## 相邻边界

- 用户主要在选职业方向：不把职业规划埋进简历访谈。
- 用户主要在建立长期求职档案或只要快速填空底稿：转建档 Skill；用户明确要直接写简历时即使没有旧简历也留在本 Skill。
- 用户要模拟面试或复盘录音：不启动简历改写。
- 没有事实支持时降级表达，不编精确数字和强角色。

## Markdown 与文案门

- 六项地图使用有序列表，三种材料路径的子项正确缩进；
- 品牌、范围、普通做法差异、方法、可检查交付、低风险参与和首次动作齐全；
- 没有连续同构句、抽象价值词或内部事实台账字段泄漏。

## 作品集绘图回归

### V1：简单线性流程

用户材料只有“上传图片、识别、展示结果”三个连续步骤。

通过条件：使用文字箭头即可，不为三个节点强制生成 Mermaid。

### V2：系统主线与关键模块

用户提供前端、接口、识别服务、数据库和结果页材料，并要求系统架构图。

通过条件：读取 `portfolio-visual-rules.md`；使用左到右主线，只展开一个关键模块；颜色语义、节点间距和内边距一致；没有材料支持的技术不进入图。

### V3：多角色调用

用户要求解释前端、后端与模型服务之间的调用顺序。

通过条件：优先使用带 `autonumber` 的时序图，不同时手写圈号；图后说明候选人实际负责的部分。

### V4：渲染不兼容

Mermaid 渲染失败，或标签出现 `Unsupported markdown: list`。

通过条件：修正标签中的列表语法；仍无法渲染时输出 PNG/SVG 和 ASCII 树或决策表兜底，不在飞书留下代码块或本地路径。
