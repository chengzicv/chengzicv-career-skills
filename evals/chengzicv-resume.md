# 简历顾问 Evals

只在创建、修改或回归本 Skill 时读取。正常简历任务不加载。

## 首次体验

### C1：旧简历与 JD 齐全

用户提供旧简历和 JD，要求直接优化。

通过条件：

- 回复从“你好，我是橙子简历顾问 skills。”开始，前面没有标题、材料摘要或确认；
- 锁定正文逐字完整输出，六类卡点、三种材料路径、事实底线和交付清楚；
- 公共介绍后立即建立事实台账并开始产出可用稿，不先做长访谈，不让用户重新概述；
- 参考案例、JD 和行业常识没有被写成用户事实；
- 后续回复不重复公共介绍。

### C2：没有材料

用户只说“帮我写简历”。

通过条件：只输出锁定正文；正文末尾已经给出材料入口，不再追加第二段欢迎语或材料清单。

### C3：用户说没有经历

用户说“我三无，没东西可写”。

通过条件：

- 先完整输出锁定正文；
- 随后使用经历雷达让用户选真实做过的场景，不要求自由列举人生经历；
- 一次只问一个问题，允许跳过，不把案例写成用户经历。

### C3b：零材料但只想先建档

用户说“我先不急着写岗位版简历，想把大学做过的东西慢慢收集起来，随时补充和暂停”。

通过条件：转 `chengzicv-profile`；不启动岗位版简历策略、完整 STAR 补强或作品集制作。

### C4：只改一段经历

用户提供一段项目描述要求优化。

通过条件：完整介绍后直接给当前事实能支持的改写；只有缺失事实会改变表达强度时才追问一个问题。

### C5：完整岗位版优化必须成套交付

用户提供旧简历和 HR 实习生 JD，说“按你们最佳流程完整优化”。没有提供截图、PPT 或现成作品集。

通过条件：

- 先给当前事实支持的岗位版简历，不因缺作品集而阻断；
- 同时交付修改与风险说明，以及至少一个明确标注“参考示例，不是你的经历”的同岗位示例或等价真实前后 diff；
- 明确判断作品证明属于 A 真实作品集、B 岗位工作样本或 C 最小作品构建计划中的哪一种；
- 没有真实作品材料时不得伪装成 A，也不得把示例方案写成用户任职经历或业绩；
- 不能只返回润色后的简历正文便宣告完整流程结束。

### C6：真实项目材料触发作品集

用户提供简历、JD、项目截图、演示视频和测试记录，要求完整处理。

通过条件：作品证明状态为 A；外发作品集只使用可核验事实与媒体，内部准备手册可以补充理解与练习；两者从同一事实正文核心生成但不能机械删减互转。

### C7：局部改写不强制扩张

用户只要求把一条经历压缩成一行。

通过条件：交付干净改写和必要说明即可；除非用户需要理解或该改写风险较高，不强制生成完整作品集、长报告或多文件包。

### C8：公司内垂直虚拟案例

用户先否定一份泛化工作样本，再说：“案例不够好，调研这个方向，模拟一家公司，把项目放在公司里，给我更垂直、更深的参考简历和作品集。”

通过条件：

- 同时读取 `fictional-resume-case.md` 与 `deep-company-fictional-case.md`；
- 因用户明确要求调研，先核验真实产品/商业形态、专业规则和当前岗位要求，不用行业印象直接编案例；
- 公开事实、虚拟公司、虚拟项目和用户真实事实四层分开，来源和模拟数据不会互相冒充；
- 虚拟公司写清业务模式、规模、渠道或客户、原产品/服务、经营基线、团队分工和候选人汇报关系；
- 项目由公司已有经营问题触发，包含业务门槛、预算或时间上限和停止条件；
- 候选人职责、主管决策和专业团队职责清楚，初级候选人不承担公司战略或全部团队成果；
- 漏斗、收入、成本、贡献、交付或库存数据可以重算，不把意向当订单、贡献当净利润、团队结果当个人业绩；
- 至少写出两个有比较依据的业务取舍，其中至少一个为没有扩大投入、没有补货、暂停或停止；
- 默认交付内部调研与设计说明、虚拟案例简历、外发作品集和内部面试准备手册四份材料；
- 文件名和标题明确包含“虚拟案例”，且案例内容没有迁入用户真实简历；
- 不复用上一次案例的行业、公司、数字和项目结构细节，只复用深度框架。

## 相邻边界

- 用户主要在选职业方向：不把职业规划埋进简历访谈。
- 用户主要在建立长期求职档案或只要快速填空底稿：转建档 Skill；用户明确要直接写简历时即使没有旧简历也留在本 Skill。
- 用户要模拟面试或复盘录音：不启动简历改写。
- 没有事实支持时降级表达，不编精确数字和强角色。
- 完整岗位版优化必须完成参考示例与作品证明状态；局部改写仍允许按用户范围缩短。

## Markdown 与文案门

- 六项地图使用有序列表，三种材料路径的子项正确缩进；
- 品牌、范围、普通做法差异、方法、可检查交付、低风险参与和首次动作齐全；
- 没有连续同构句、抽象价值词或内部事实台账字段泄漏。

## 作品集绘图回归

### V1：简单线性流程

用户材料只有“上传图片、识别、展示结果”三个连续步骤。

通过条件：使用文字箭头即可，不为三个节点强制生成 Mermaid。

### V2：系统主线与关键模块

用户提供前端、接口、识别服务、数据库和结果页材料，并要求系统架构图。

通过条件：读取 `portfolio-visual-rules.md`；使用左到右主线，只展开一个关键模块；颜色语义、节点间距和内边距一致；没有材料支持的技术不进入图。

### V3：多角色调用

用户要求解释前端、后端与模型服务之间的调用顺序。

通过条件：优先使用带 `autonumber` 的时序图，不同时手写圈号；图后说明候选人实际负责的部分。

### V4：渲染不兼容

Mermaid 渲染失败，或标签出现 `Unsupported markdown: list`。

通过条件：修正标签中的列表语法；仍无法渲染时输出 PNG/SVG 和 ASCII 树或决策表兜底，不在飞书留下代码块或本地路径。
