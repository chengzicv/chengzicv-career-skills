# ChengziCV 总入口 Evals

## 应路由

1. “我快毕业了，不知道该做什么，也没有简历。”应先进入职业规划，且只索取当前决定与最近期限。
2. “后天面试，这里有简历和 JD，先帮我调研公司、准备完整答案和两份文档。”应进入面试前调研与冲刺，不用模拟训练替代文档交付。
3. “后天面试，这里有简历和 JD，直接问我问题。”应优先处理最近面试；根据轮次在初筛或专项训练中只选一个。
4. “刚面完，这是录音。”应进入真实面试复盘，不从职业规划重新开始。
5. “方向明确，帮我把项目整理成简历和飞书作品集。”应进入简历 Skill，并触发飞书环境检测协议。
6. “我是大三学生，没有简历，先帮我把大作业、奖状和证书整理成求职档案。”应进入建档 Skill，不直接生成岗位版简历。
7. “我什么都没有，但主要是不知道考公还是找运营工作。”核心问题是方向判断，应进入职业规划，不强制先补完整档案。

## 首次体验

1. 用户只调用 `$chengzicv`：首次介绍应说明“1 个总入口 + 7 个执行 Skills”，可展示公开调用名与推荐路径，但不得让用户研究内部路由或先手动选择模式。
2. 用户应能从介绍中认出至少一种处境，并知道对应会拿到什么：建档是“档案快照、材料索引与待确认项”；方向是“少量方向假设和现实验证动作”；材料是“简历正文、证据缺口和追问风险”；面试准备是“面试官展示稿与候选人冲刺稿”；初筛是“原话依据的判断与短复练”；专项训练是“连续追问、教学和变式复测”；真实面试是“原话诊断、逐题面经和下一场重点”。
3. “我后天有 HR 面，简历和 JD 在上面。”介绍后应优先路由到初筛模拟并直接开始，不得再问用户选哪一种服务，也不得强制职业规划或完整链路。
4. “我只有一点迷茫，不知道从何开始。”介绍后只索取当前背景或现有材料、最着急的问题和最近不可错过的日期；不得再次罗列七个执行入口或索取完整简历。
5. 用户第二次回复材料后，不重复完整介绍；应从材料和期限所支持的当前一步继续。
6. 首次介绍可以说明档案能随时补充、暂停和导出快照，但不得承诺普通聊天跨会话自动记忆。
7. 总入口完成路由后不得在同一对话中再次输出目标执行 Skill 的完整公共介绍；应把总入口介绍视为套件级 onboarding 并直接开始。用户直接调用执行 Skill 时，仍输出该 Skill 自己的完整首次介绍。
8. 首次可见文字必须从“你好，我是橙子 CV 求职导航。”开始，不得输出“首次使用公共介绍”“锁定正文”或文件说明标题。

## 不应阻断

1. 用户已经给出材料时，不要求他研究七个执行 Skill 或重新调用命令。
2. 用户只说“帮我找工作”时，不展示内部路由表，只问现有材料与最近期限。
3. 有截止日期时，不强迫从职业规划开始走完整链路。
4. 未显式调用 `$chengzicv` 的明确简历、职业规划或面试任务，不应由总入口抢走对应子 Skill 的直接路由。

## 旅程契约回归

### J1：锁定岗位不得被旧简历覆盖

用户先明确“这次只投人力资源实习生”，随后提供一份以 Java 和前端项目为主的软件工程简历。

通过条件：目标岗位保持为用户已确认的人力资源实习生；简历和面试阶段可以提取沟通、协作、学习等迁移证据，但不得把目标切回开发岗，也不得反复要求用户重新确认是否转岗。

### J2：阶段交接不重新盘问

职业规划阶段已经确认目标岗位、最近期限和一份 JD，随后转简历优化。

通过条件：交接包含目标及其确认状态、期限、JD、已有事实和关键未知；简历 Skill 直接开始，不重新索取目标岗位、截止日期或同一份 JD。

### J3：可以从中间开始

用户已经有简历和后天的面试安排，首次进入总入口。

通过条件：直接进入对应面试阶段；不要求先建档、做职业规划或补齐完整简历流程。

## 依赖回归

- 核心运行不得强依赖非 ChengziCV Skill 或作者本机绝对路径；可选云发布能力必须可检测，并在缺失时回退为本地源稿。
- 没有持久化 Runtime 时，建档 Skill 必须交付可复制快照，不得假装自动恢复历史档案。
- 未安装 `lark-cli` 时，飞书作品集仍应先完成本地双文档，并给出经同意安装与网页回退两条路径。
- Python 校验器在没有第三方包的标准 Python 环境中可运行。
- `chengzicv/references/journey-contract.md` 可以从总入口直接发现；子 Skill 内部更新不得改变目标锁定、最低交付、阶段完成门和交接字段。
