# 腾讯游戏招聘调研案例骨架

本文件沉淀一次“软件服务公司招聘专员支持腾讯游戏相关项目”的调研结构，只作为颗粒度示例和检索起点，不是腾讯当前组织、产品、HC 或人才政策的事实库。

凡是复用天美、光子、魔方、北极光、NExT Studios、腾讯游戏/IEG 等名称前，都必须重新查看腾讯官方页面、官方招聘和目标 JD，确认名称、关系、产品与招聘状态。案例中的竞品、学校、专业和能力画像同样需要按城市、岗位和时间刷新。

## 这个案例为什么需要双文档

- 面试官要看的是：候选人能否把陌生业务拆成招聘动作，是否具备用人需求理解、人才地图、数据复盘和候选人沟通能力；
- 候选人要准备的是：怎样介绍自己的转岗或招聘经历，怎样回答全流程招聘、业务沟通、稀缺人才寻访和压力场景；
- 两者共享事实，但私密话术、弱点和补救不能出现在展示稿。

## 研究顺序

1. 明确劳动关系、服务公司、腾讯项目和实际用人团队之间的关系；
2. 从官方资料确认腾讯游戏业务及目标工作室/产品线，不先照搬网上组织图；
3. 对每条目标业务拆岗位族、任务、技术/工具和交付证据；
4. 为每个岗位族寻找具体竞品公司的对应业务线或产品，而不是只列公司；
5. 形成公司词、产品词、职位同义词、技术词和证据词组合；
6. 研究候选人可能关心的项目内容、技术挑战、地点、流程和成长，同时把薪酬、HC、汇报线等列为待内部确认；
7. 把人才地图转成需求澄清、渠道选择、寻访、沟通和漏斗复盘动作。

## 面试官稿应展示的核心链路

```text
腾讯相关业务信号
→ 工作室/产品线及岗位族
→ 竞品公司的对应业务线
→ 可搜索关键词与能力证据
→ 候选人顾虑和真实吸引点
→ 招聘执行与数据复盘
```

这张图的价值不是证明记住多少工作室，而是证明可以把业务信息转成招聘判断。

## 候选人稿应回答的核心问题

- 为什么从现有经历转向或继续做招聘；
- 怎样理解“精准招聘”，怎样和用人经理把模糊需求拆清楚；
- 面对技术、美术、策划、产品/项目等不同岗位，画像和渠道怎样变化；
- 没有某类游戏岗位招聘经历时，怎样用相邻技术招聘证据和学习方法诚实承接；
- 怎样主动寻访、提高回复、处理候选人顾虑并维持体验；
- 怎样看招聘漏斗，如何定位是画像、渠道、话术、流程还是 Offer 环节的问题；
- 怎样处理业务催促、面试官反馈慢、候选人反悔或薪资不一致；
- 入职前两周准备确认什么、建立什么台账和复盘节奏。

## 已知失败与回归

- 把四份近似文档同时保留，用户不知道看哪份；
- 图像像复杂海报，不能快速说明行业和招聘动作；
- 只写竞品公司名，没有具体业务线与检索词；
- 把公开推断写成腾讯内部事实；
- 答案充满“协同、赋能、闭环”，候选人无法自然说出口；
- 腾讯文档保留字面 `**` 或 Mermaid 代码，发布后没有反向检查。

未来处理相似任务时用这些失败做检查，不复用当时的具体业务结论。
