# 招聘平台话术交付与审计契约

## 1. 输入优先级

优先复用当前对话已经出现的信息：

1. 用户本轮指定的 JD 或岗位。
2. 用户确认的岗位版简历与事实。
3. 已核验作品、链接和结果。
4. 旧简历或通用档案。

顾问建议、模板、其他候选人案例和 JD 要求都不是用户事实，不能写成候选人做过。

如果缺少 JD：

- 已有明确岗位方向时，先给方向基础版，并标明“需要具体 JD 才能做单岗微调”。
- 连岗位方向也没有时，只问一个会改变结果的问题：目标岗位是什么或贴出 JD。

## 2. 默认交付

### 单个 JD

默认交付四部分：

```text
一、初次触达 A/B 两版
- 可直接发送

二、已读不回跟进
- 新增信息点
- 可直接发送

三、被拒后反馈询问
- 可直接发送
```

候选人层级、岗位层级、信号选择、前 15 字和字符数都属于内部分析，不默认写入交付。用户只要一句可复制话术时，直接给完整可发送内容；只有用户明确要求查看方法或审核过程时才展示分析。

### 完整沟通包、追问话术或顾问交付

除初次触达外，至少按候选人的真实求职场景交付：

```text
一、招聘者回复后的定制续接
- 索要简历
- 询问相关经验/求职动机
- 核对基础条件（仅写已确认项）

二、候选人主动核岗
- 真实职责
- 试用期或核心考核
- 候选人明确关注的工作边界

三、流程推进
- 对方表示“可以聊聊”后的承接
- 发完简历后的电话/文字选项
- 对方约电话但没有打来
- 接受或调整面试
- 等通知
- 面试后进度跟进

四、结束场景
- 已读不回
- 明确拒绝后的反馈询问
- 对方反馈后的收口
- 岗位关闭或暂停

五、通用替换模板
- 标明方括号变量
- 说明触发条件和停止条件
```

不需要机械覆盖所有可能场景。先根据候选人的岗位方向、事实和边界选出最可能发生、最影响决策的场景，再补通用模板。每条消息都要标注“什么时候发”，不能只给一组无上下文句子。

### 同一方向多个 JD

- 每个 JD 单独设计开头信号和初次触达，但交付时只输出完整可发送话术。
- 共用事实主干时允许复用后半句，但不能把所有岗位写成同一条模板。
- 共享一套已读不回与拒绝反馈话术即可；有岗位特有证据时再单独生成。

### 多个岗位方向

- 按岗位方向分组，每组使用对应简历事实。
- 不把一个方向的强结果迁移到另一个不相关方向。
- 默认每个方向给 1—2 条初次触达，不需要机械凑满版本数。

## 3. 平台长度

- **BOSS 直聘**：默认内部审计开头约 15 个可见字符；完整正文可以继续补证据、意向和回复入口，不再机械限制为 60 字。过长时拆成 2—3 个短消息气泡。
- **其他招聘平台**：用户提供实际预览长度时按该长度；未知时保证第一短句已有实质信号，不声称平台固定只显示 15 字。
- 英文字母、数字、标点和空格均按一个 Unicode 字符计入机械审计；真实 UI 宽度可能不同，最终以用户当前客户端预览为准。

## 4. 初次触达审计

每条必须通过：

- [ ] 只看开头约 15 个字符就能判断一个明确岗位匹配点。
- [ ] 没有以“您好、你好、我是、看到贵司岗位、对贵公司感兴趣”开头。
- [ ] 预览区的公司名、学校名或产品名是招聘者大概率能识别的；无法识别时已改成行业、动作或交付物，没有把普通公司写成头部。
- [ ] 最强数字不会制造明显层级、薪资或稳定性风险。
- [ ] 每个动作、数字和作品都有候选人事实支持。
- [ ] 正文信息密度合理；过长时已拆成短消息气泡。
- [ ] 没有空泛的“匹配度高、经验丰富、学习能力强”。
- [ ] 给出了低压力回复入口，或自然引导查看简历/作品。

机械检查使用：

```bash
python3 scripts/preview_audit.py \
  --text '待检查的话术' \
  --preview-length 15 \
  --max-length 120
```

脚本只检查字符和无效开头，不替代事实、岗位匹配和风险判断。

## 5. 跟进审计

收到招聘者回复：

- [ ] 先直接回答对方当前问题。
- [ ] 只补一项最相关证据，不把整份简历重新粘贴一遍。
- [ ] 每条消息只推进一个下一步。
- [ ] 到岗、薪资、城市和工作边界均有事实依据。

候选人主动核岗：

- [ ] 一次只问一个影响是否继续的决定性问题。
- [ ] 问题指向真实工作场景或考核，不泛问“岗位职责是什么”。
- [ ] 用中性事实核验，不用情绪化或对抗式表达。

已读不回：

- [ ] 与初次触达相比增加了一个新信息点。
- [ ] 如写“看到您看过消息”，语气只是客观承接，没有质问为什么不回。
- [ ] 需要强调意向时拆成 2—3 个短消息气泡，而不是一整段压迫式长文。
- [ ] 重复触达时每轮目的不同，并根据普通岗位、重点岗位或已释放意向选择不同频率。
- [ ] 有文字/电话的低成本入口，也有岗位关闭或暂不匹配的退出空间。

明确拒绝：

- [ ] 问题足够小，最好提供 2—3 个原因选项。
- [ ] 说明不方便回复也没关系。
- [ ] 不争辩、不卖惨、不试图迫使翻盘。

## 6. 文件交付

- 默认直接在对话中输出可复制文本。
- 用户要求批量交付、顾问包或保存文件时，默认生成 Markdown。
- 外发话术文件只放可发送内容和必要使用说明；层级判断、风险、测试假设可放同一文件的内部说明区，或按用户要求分开。
- 不自动生成 DOCX、PDF 或表格，除非用户明确要求。
