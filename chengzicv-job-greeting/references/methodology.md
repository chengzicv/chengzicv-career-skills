# 招聘平台招呼语底层方法论

## 1. 它不是 Cover Letter

Cover Letter 是随邮件或申请材料提交的正式求职信，目标是完整解释动机、经历与岗位连接。招聘平台招呼语的第一目标更窄：

```text
消息被扫到 → 预览区出现有效信号 → 招聘者点开 → 低成本回复 → 才有机会看简历
```

因此不能把求职信缩短后直接塞进聊天框。平台消息先解决注意力和匹配判断，正文才补证据与意向。

## 2. 预览区是信号区

橙子 CV 历史测试和教学材料把 BOSS 未打开消息时的前约 15 个汉字作为默认设计区。平台、设备和版本会变化，所以“15”是 BOSS 的默认审计长度，不是所有平台永恒不变的 UI 定律。

稳定原则是：即使后文全部隐藏，开头可见部分也要让招聘者判断出一个明确匹配点。

无效开头：

- 您好 / 你好
- 我是某大学某届学生
- 认真看了 JD
- 对贵公司很感兴趣
- 想应聘这个岗位

这些内容可以后置或省略，因为它们不能说明“为什么值得点开”。

## 3. 信号选择公式

候选信号来自以下五类，不要求每条全部出现：

```text
硬门槛或身份 + 岗位动作 + 对象/工具/行业 + 可信结果 + 可验证交付物
```

优先选择能直接回应 JD 的 1—2 项：

- 年限或身份：2 年采购、应届内容运营、同赛道实习。
- 岗位动作：寻源、投标复核、接口开发、选题发布、数据清洗。
- 对象/工具/行业：供应商、医院软件、Spring Boot、Excel、快消。
- 结果：项目数量、曝光、转化、交付周期、问题解决。
- 交付物：作品集、Demo、SOP、报告、图纸、台账。

“985”“目标专业”“大厂同岗实习”等身份只有在确实构成硬筛优势时才进入预览区。普通学校名称和届次通常后置，因为它们占位但不提高匹配判断。

公司名、产品名同样不是默认钩子。专有名词只有在招聘者扫一眼就能识别、并因此提高匹配判断时才进入预览区。写进开头前只问三件事，按判断选措辞，不要对照固定行表填空，也不要输出分类表：

1. 招聘者大概率认不认识这个名字？
2. 不认识时，有没有公开可核实的依据能叫「本行业头部」？
3. 这个行业跟目标岗位对不对口？

认识，可写公司名。不认识但能核实头部且行业对口，写「xx行业头部」加岗位动作，不写公司名。不认识也不是头部但行业对口，写「xx行业公司」加项目动作。行业也不对口，丢掉公司，改写可迁移动作、工具或交付物。禁止把普通公司写成头部，禁止把内部简称、分公司全称或招聘者不熟的品牌硬塞进前约 15 字。

例如，教育信息化公司「超星」对多数 AI 产品招聘者构不成识别信号；有公开依据时可写「教育信息化头部做过AI训练原型」，而不是「超星做过AI训练原型」。字节、腾讯等大众能立刻认出的名字才直接进预览区。例子只解释规则，不作为必须套用的公司名单。

## 4. 匹配感优先于实力感

在写最大数字之前，先比较候选人与岗位层级：

| 候选人与岗位关系 | 预览区策略 |
| --- | --- |
| 层级匹配 | 可前置最能证明同岗能力的结果或项目量 |
| 候选人略低 | 写相似任务、真实工具和低学习成本，不硬凑大成果 |
| 候选人略高或明显过强 | 降低管理规模和战略信号，改写为一线动作与可落地职责 |
| 行业不垂直 | 前置可迁移动作和相似场景，不假装有目标行业经验 |

数字是否有价值，不看数字大不大，而看招聘者会把它解释成匹配信号还是风险信号。

例如，投初级采购执行岗时，“管理 1.9 亿采购额”可能引发薪资、稳定性和层级顾虑；“做过询比价、供应商沟通和交付跟进”反而更像能接住工作的人。投专家岗时，同一个金额才可能成为强证据。

## 5. 初次触达

推荐结构：

```text
预览信号 + 1—2 项匹配证据 + 简短意向或低压力问题（有在线材料时可换成材料钩子）
```

要求：

- 先写证据，后写学校、届次和“想应聘”。
- 每条只服务一个岗位方向。
- 开头约 15 个字符只做内部设计和验收，默认不在用户交付里额外输出“预览文本”。
- 开头之后可以继续补充岗位动作、真实结果、JD 匹配和沟通意向，不要为了追求极短而把证据删空。
- 单段明显过长时，拆成 2—3 个短消息气泡；作品链接可放末尾或下一条消息，不要挤掉开头信号。
- 低压力问题应让对方容易回答，例如“方便看下简历吗”“岗位目前还在推进吗”，不要要求对方长篇解释。

### 先选派别，再写字

初次触达常见三种写法，各自靠不同的东西说服对方。先判断收件人，再选一派写到底，不要三种混着用：

| 派别 | 靠什么说服 | 写法 | 适合的收件人 |
| --- | --- | --- | --- |
| 证据密度 | 证据推理 | 交付周期、前后对比、规模数字往前放 | 技术负责人、业务负责人，想看你做过什么 |
| 低门槛对话 | 让对方好回 | 一句人设加一个能一句话回答的问题，少放数字 | 小公司老板、消息很多的 HR |
| 资历背书 | 说话人可信 | 投资、名次、头衔、知名公司依次排开，书面语 | 按背书快速筛人的 HR、猎头 |

收件人看不出时，默认用证据密度派。招聘者在列表里扫消息时投入很低，主要靠外围线索判断，所以资历背书派对 HR 往往有效；但背书一旦被查出不实，整条消息的可信度会一起崩掉。因此背书派的每个投资、名次、头衔都必须能在简历、作品或截图里找到，找不到的不写。

**别漏掉“对方能得到什么”。**推销信的完整语步是：建立信誉、介绍能力、提供诱因、附上材料、请求回应、礼貌收尾。候选人自己写的话术最常缺的是提供诱因，通篇讲“我是谁”，没有一句讲对方为什么需要。资历背书派尤其要补上半句，例如“可以直接承接运营侧的提效需求”“入职就能接手小程序迭代”。诱因必须由候选人事实支撑，不替对方许诺业绩。

同一候选人投多个岗位时，按 [事实模块库与按岗位排序](module-library.md) 拼装，不整段重写。

### 结尾的两种写法

1. **低压力问题**：“方便看下简历吗”“岗位目前还在推进吗”。适合低门槛对话派，也是没有在线材料时的默认写法。
2. **材料钩子加联系选项**：“在线简历已附完整项目数据与链接，欢迎查看。如果觉得合适，随时电话或加微信聊都可以~”适合证据密度派和资历背书派，前提是候选人确实有在线简历、作品或链接可看。

联系选项按收件人调语气：

- 发给 HR：默认“如果觉得合适，随时电话或加微信聊都可以~”。“觉得合适”把决定权交给对方，句末一个“~”只让语气软一点，不会和前面的书面正文脱节。
- 发给技术负责人、业务负责人，或正文是很正式的资历背书写法：去掉“~”。
- 不用“哦~”“呀”这类口语助词收尾。书面正文后突然换成聊天腔，读的人会觉得前后像两个人写的。确实想要更口语的结尾，就把它拆成单独一条消息发；对方回复后进入正常聊天，再放开用口语。
- “如方向匹配，可以交换微信详聊”也成立，但偏公文，只在收件人明显偏正式时用。

第二种可以把电话列为选项之一，例如“随时电话或交换微信详聊”，因为它只是给对方一个更省事的入口。但不能写成要求对方答复的问句，例如“能电话聊一下吗”“什么时候方便打电话”，电话升级仍按第 7 节的时机判断。

## 6. 已读不回

已读不回可能是忙、岗位优先级变化、消息过多或仍在观察，不能直接判断为拒绝。

跟进强度取决于岗位价值和对方释放的信号：

| 场景 | 默认节奏 | 每轮必须做什么 |
| --- | --- | --- |
| 普通冷岗位，仅显示已读 | 约 24—48 小时后跟进一轮 | 补一个新证据，给低压力入口 |
| 重点意向岗位，岗位仍活跃 | 2—4 天内可触达 2—3 次 | 每次换证据或目的，不原样催促 |
| 对方已索要简历、说“可以聊聊” | 在数小时后或合理工作时段内推进 | 提供文字或短电话选择 |
| 对方主动提出电话但没有打来 | 当日温和提醒，次日仍无进展可再确认 | 描述事实、表达意向、提供随时联系和岗位关闭出口 |

一轮跟进可以拆成三条短消息，并适当间隔，不合并成长段：

1. 自然承接或说明来意；
2. 补一个岗位直接相关的新信息；
3. 表达真实意向并给回复、电话或退出选项。

可以中性写“看到您看过我的消息”或“前面有提到电话沟通”，但不要质问“为什么不回”，也不要用相同内容连续刷屏。目标是提高在招聘者有空、有意向的窗口中被重新注意到的概率。

招聘者的“在线/离线”状态可能延迟、隐藏或不代表当下是否方便处理招聘消息，不能据此推断对方没有兴趣。跟进节奏应依据已经发生的沟通信号和合理工作时段，而不是守着在线图标。

## 7. 从文字沟通升级到电话

电话不是冷启动动作。上来就要求电话，会让招聘者先承担时间成本。初次消息结尾把电话列为可选入口不算要求，见第 5 节“结尾的两种写法”。主动询问能否通电话，更合适的节点是：

- 对方看过简历并表现出初步意向；
- 对方回复“可以聊聊”；
- 对方主动提出电话沟通；
- 文字已经无法高效澄清核心问题。

降低电话门槛的表达公式：

```text
随时可接 + 只需约2分钟 + 电话或文字都可以 + 合适再继续推进
```

对方提出电话却没有打来时，使用非暴力沟通四步：

```text
观察：前面提到电话沟通，但暂时还没接到
感受：担心错过、心里有点没底
需要：确实有意向，希望知道是否继续推进
请求：有空随时联系；岗位暂停或关闭也可以直接告知
```

不把猜测写成事实，不说“您不愿意聊”“您在吊我”。

## 8. 明确拒绝或面试后被拒

追问的目标是拿到下一次可用的反馈，不是强行翻盘。

设计原则：

- 把问题缩小成容易回答的选项，如行业经历、岗位层级或核心技能。
- 明确给出“不方便回复也没关系”的出口。
- 建议拆成 2—3 个短消息气泡：感谢、选项式提问、退出空间。
- 对方回复后道谢并结束；明确表示不便反馈时停止。未回复时，重点岗位可再做一次极短收口，不无限追问。

## 9. A/B 测试与漏斗复盘

测试话术时一次只改一个变量：

- A 版前置同岗经历。
- B 版前置可验证结果或作品。

只比较相近岗位、相近公司层级和相近时间段，记录：

```text
有效触达数 → 已读/点开 → 回复 → 索要简历 → 约面
```

不同岗位、公司规模和时间段的数据不能直接混合。

样本量要够才下结论。回复率从 10% 提到 20% 这种幅度，每个版本大约要发 200 条才能比较可靠地分出高低；每版只发二三十条时，差异多半是噪声，只能当成继续测的线索。候选人每周投递量较小时，宁可两版轮流用满两到四周再比，也不要发了十几条就换话术。

每条投递在记录表里写上用的是哪一版、哪一派，否则事后无法归因。历史材料中的“500+次测试、已读率约提升 14%”缺少完整分组和同期控制，只作为“预览区值得测试”的内部观察，不向用户承诺固定提升。

如果多位招聘者反复给出同一个拒绝原因，应把它当成岗位池信号，而不只是话术问题。例如多次得到“更偏好垂直行业经验”，说明当前岗位层级或企业要求可能较高：继续测试相邻行业的同时，增加同领域公司和更初级岗位，不要只反复改开场白。

版本冲突按以下方式处理：

- 早期资料把“前15字”写成固定 UI 事实；后期资料提醒界面会变化。本 Skill 将其作为 BOSS 默认设计与审计长度，同时保留平台可配置性。
- 早期工具包强调三条消息和反复触达，后期整理强调低压力与停止高频催促。新版按信号分层：普通冷岗位一轮；重点岗位 2—3 次有效触达；对方已释放电话意向时允许当日和次日连续推进。无新增信息的重复催促仍然禁止。
- 早期资料引用约 14% 提升；后期升级版指出缺少完整实验控制。本 Skill 不把该比例写成普遍结论。
- 早期投递指南把「具体公司」写成默认第一钩子。新版先判断识别度：大众能认出才写公司名，否则改成行业或项目动作，不把决策表当成必须输出。
- 早期版本规定初次触达以低压力问句结尾。2026-11-05 起允许第二种结尾：有在线材料时用材料钩子加联系选项，电话只能作为选项出现，不能写成问句。
- 早期版本每次整段生成话术。2026-11-05 起，同一候选人多岗位投递时先建事实模块库，模型只排序和写开头。
