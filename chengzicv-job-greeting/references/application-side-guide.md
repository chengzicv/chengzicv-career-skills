# 候选人投递侧指南规范

## 1. 适用场景

当用户需要一份可直接转发给候选人的投递侧文档、后续投递指导、招聘平台使用说明或求职沟通包时，使用本规范。

这不是岗位搜索报告，也不是把所有求职知识堆成手册。默认目标是让候选人看完即可执行：知道每天怎么投、第一句话怎么写、招聘者回复后怎么推进、如何记录结果，以及怎样补一份真实作品。

## 2. 标题与对象

标题必须指向当前候选人，不使用“银行岗位投递与后续行动指南”一类泛标题。

默认格式：

```text
# {候选人姓名或简历中的代称}-{岗位方向}投递侧指南
```

示例：

```text
# 黄XX-银行岗位投递侧指南
```

- 简历使用脱敏姓名时，标题继续使用脱敏代称，不根据文件名、历史目录或其他材料擅自还原真实姓名。
- 岗位方向已经明确时写入标题；方向过长时压缩为招聘者和候选人都能理解的短名称。
- 标题下可保留一行候选人画像，例如届次、专业、主投方向和关键偏好，但不要把内部风险标签放在外发文档中。

## 3. 默认交付结构

用户没有指定其他范围时，只交付以下五章，并从一到五连续编号：

```text
一、建议投递节奏
二、招聘平台初次打招呼
三、招聘者回复后怎么推进
四、建立投递台账
五、可以做作品，但必须真实
```

不要默认增加资格政策、岗位地图、简历版本、笔面准备、十四天计划或最终清单等其他章节。用户明确要求扩展时再增加；用户点名保留或删除章节时，按其选择重新编号。

默认保存为 Markdown；内容使用第二人称，保持可直接转发，不展示层级判断、风险分、生成逻辑、预览审计报告等内部分析。

## 4. 各章内容规范

### 一、建议投递节奏

先定义“有效投递”：岗位仍在招聘、候选人满足基本条件、城市可接受、职责与履历有连接、公司主体明确。不要用纯数量替代匹配度。

可为普通应届或初级候选人提供以下起始节奏，再根据岗位供给、地区和用户要求调整，不把它写成所有人的强制 KPI：

- 银行、央国企或企业官网：每天完成 3—5 份高质量报名或岗位核验。
- 智联、BOSS 等平台：每天投递 15—25 个匹配岗位。
- 每天挑选 2—3 个重点岗位，阅读完整 JD 并使用定制话术。
- 每天集中处理一次跟进，晚上用约 10 分钟更新投递台账。

提醒候选人优先近期发布、职责清楚、招聘仍在推进的岗位。可以建议在工作时段主动沟通，但不得承诺特定投递时间必然提高回复率。

### 二、招聘平台初次打招呼

默认提供目标岗位 A/B 两版；候选人还有明确相邻方向时，再各给一版。没有具体 JD 时标明是方向基础版，有 JD 时按 JD 重新选择开头信号。

先选招聘者能立刻识别的匹配信号，不要默认把公司名放第一位：

```text
可识别的公司 / 可核实的行业头部 / 行业+项目动作
→ 最相关的岗位动作
→ 连续经验或相邻经历
→ 2—4 个可信数字
→ 岗位意向或低压力回复入口
```

例如，候选人同时拥有招商银行网点实习和校园客户开发经历时，可按“招行实习 → 厅堂分流与客户回访 → 两年客户开发 → 回访、咨询、意向和转化数字”的顺序组织。若实习公司招聘者不认识，改成“银行网点做过厅堂分流”，不要写内部公司全称，也不要把普通公司写成头部。

初次触达继续遵守底层方法：

- 不以“您好”“你好”“我是”“看到贵司岗位”“对贵公司感兴趣”开头。
- 公司名不是默认钩子；招聘者不认识时改写为行业或项目动作，禁止把普通公司写成头部。
- BOSS 默认检查开头约 15 个可见字符是否已有具体匹配信号。
- 正文补 1—2 项不重复证据，结尾给“方便看一下简历吗”“岗位目前还在推进吗”等低压力入口。
- 信息过长时拆成 2—3 个短消息气泡，每条只承担一个作用。
- 生成后使用 `scripts/preview_audit.py` 检查字符与无效开头，再人工核对事实、层级和岗位匹配。

### 三、招聘者回复后怎么推进

只保留候选人最可能遇到的场景，默认覆盖：

- 对方索要简历；
- 对方询问相关经验或销售经验；
- 对方表示“可以聊聊”；
- 对方核对毕业、城市、到岗或就业状态；
- 已读不回；
- 明确拒绝后的反馈询问。

每条话术标明触发场景，并遵守：先回答当前问题，补一个最相关证据，只推进一个下一步。

普通冷岗位初次触达后约 24—48 小时最多补充一轮；重点岗位可在 2—4 天内做 2—3 次不同目的的触达，但每次必须增加新信息。不得用“为什么不回复”“能不能给个机会”等施压表达。

城市、到岗、劳动合同、社保、薪资等尚未确认时，使用明确的方括号变量并提醒候选人替换，不擅自承诺。

### 四、建立投递台账

至少提供以下字段：

```text
日期｜公司或银行｜岗位｜城市｜渠道｜简历版本｜硬条件｜当前状态｜下次动作｜结果原因
```

统一状态建议：

```text
待投递 → 已投递 → 已读 → 已回复 → 笔试 → 面试 → 等结果 → Offer／拒绝／关闭
```

同时提供简短漏斗诊断表，帮助候选人区分：

- 大量未读：开头信号、岗位活跃度或渠道问题；
- 已读不回复：岗位匹配、届次、硬条件或竞争问题；
- 有回复不约面：在线简历、求职条件或经历解释问题；
- 官网无结果：资格筛选、志愿选择或地区竞争问题；
- 有面试无下一轮：转入面试复盘，不再只改简历。

提醒候选人先积累一批有效投递再判断趋势，不因三五次无回复就频繁换方向，也不把大量无效投递算成简历测试。

### 五、可以做作品，但必须真实

作品必须能实际完成和保留过程证据。对于银行客户服务或营销方向，可建议候选人基于一家目标银行官网公开资料制作一页“产品学习与客户沟通笔记”，内容可包括：

- 适用客户与申请条件；
- 公开费率、权益、限制和风险提示；
- 客户常见疑问与合规回答边界；
- 需要转介给正式员工的典型需求；
- 信息来源链接与查询日期。

作品必须标注为“基于官网公开资料的个人学习笔记”。不得写成真实用户调研、银行内部项目、已经落地的营销方案或真实经营结果。

## 5. 候选人事实与数字

- 简历、聊天或候选人明确提供的数字属于候选人主张，可以在其要求下使用；不要仅因缺少第三方证明就自动全部删除。
- 保留原有口径词，如“约、余、近、参与、协助、意向、进件”，不要擅自升级为精确统计、独立成交或最终业绩。
- 对金融、医疗、法律等受监管场景，明确本人动作与正式员工、负责人或审核角色的边界。
- 候选人明确承认没有执行、虚构或借用的项目与数字一律禁用，即使旧简历里存在也不能恢复。
- 同一个数字若可能制造层级或真实性风险，可以后置或换成过程信号；若用户明确要求保留，按其真实口径写入，并在需要时提醒准备统计周期、分母、个人与团队边界。

## 6. 文件与交付检查

交付前逐项确认：

- [ ] 标题包含当前候选人姓名或脱敏代称，而不是泛标题。
- [ ] 默认只有五个规定章节，或严格符合用户指定的章节范围。
- [ ] 文档使用第二人称，可直接转发给候选人。
- [ ] 初次触达的前约 15 个字符已有具体匹配信号；公司名可识别，或已改成行业/动作，没有把普通公司写成头部。
- [ ] 每个动作、年限和数字都来自当前候选人材料。
- [ ] 候选人明确否认或未执行的项目没有进入话术和作品建议。
- [ ] 已读不回与拒绝话术包含停止条件，不鼓励重复催促。
- [ ] 投递台账字段和漏斗诊断可直接执行。
- [ ] 作品建议标明公开来源、个人学习属性和真实性边界。
- [ ] Markdown 标题层级、引用块、列表、表格和代码块能够正常渲染。
